### 23·25를 만들지 않은 이유 — 숫자

프로덕션 실측(2026-09-10):

```
노트 28건 · 서로 다른 단지 28개 · 같은 단지 재방문 0건 · 작성자 1명
```

**같은 단지를 두 번 본 사람이 아직 아무도 없다.** 재방문 알림은 "그 단지 다시
가 볼 때가 됐어요"를 밀어 주는 기능인데, 한 번도 일어나지 않은 행동을 재촉하는
알림을 만들면 검증할 수 없는 코드에 알림 피로만 얹는다. 25(내 노트 요약)도
같다 — 사람당 노트가 여럿이어야 요약할 것이 생긴다.

둘 다 **재방문이 실제로 한 번이라도 일어난 뒤**에 다시 본다. 그때는 알림 문구를
지어내지 않고 실제 재방문 간격에서 뽑을 수 있다.

### 곁가지로 확인한 것 — 죽은 코드 하나

`/api/inspection/reports/[id]/pdf` 는 `structuredReport` 가 있는 **임장 세션**에만
답한다. 실측: 임장 세션 2건, 그중 리포트 있는 것 **0건**. 화면에서 이 라우트를
부르는 곳도 **0곳**. 노트 PDF 는 별개(`/notes/[id]/print`)라 사용자에게 빠진 기능은
없다. 이번 판에서 지우지는 않았다 — 세션 기능 자체의 거취는 별도 판단이다.

## 1. 19 — 노트에서 도구로

**전:** 노트 상세에서 AI 도구로 가는 길이 하나뿐이었다. 저장 직후 배너(`[AI-40]`)의
"AI 진단 1분"이 12종 중 유일한 딥링크였고, **그 배너는 저장 직후에만 뜬다.**
며칠 뒤 노트를 다시 열면 다음에 할 일이 사라진다.

**후:** 소유자에게 상시로 "이 노트로 이어서" 카드를 둔다 — 자주 쓰는 4종을 타일로,
나머지 8종은 허브 링크로. 각 타일은 이 노트의 단지로 바로 열린다.

지킨 것:
- **서버에서 조립한다.** 도구 제목·성격·색은 `tool-identity`/`tool-persona` 에 있고
  둘 다 큰 모듈이다. 클라이언트에서 import 하면 번들에 통째로 실린다 — 980에서
  `/analysis` 가 502KB 로 예산을 넘긴 경로가 정확히 그것이었다. 노트 상세는 서버
  컴포넌트라 문자열만 내려 준다.
- **새 규약을 만들지 않는다.** 딥링크는 워크벤치가 이미 읽는 모양(`?apt=&region=`,
  `WorkbenchClient [OPT-48]`)을 그대로 쓴다.
- **단지명도 지역도 없으면 카드를 안 그린다.** 빈 도구 화면으로 보내지 않는다.
- 12칸을 노트 화면에 다 펼치지 않는다 — 그러면 노트가 안 읽힌다.

## 2. 24 — 이 노트에 묻기

도구는 정해진 한 가지를 계산하고, 에이전트는 내 노트와 실거래를 조회해 **아무
질문에나** 답한다. 에이전트 화면(`/agent`)은 이미 있는데 **노트에서 넘어가는 길이
없어서** 질문을 처음부터 타이핑해야 했다.

노트의 사실로 질문을 채워 보낸다:
`"{단지명} 임장노트에 적은 내용과 지금 실거래를 비교해 줘"`

**자동 전송하지 않는다.** 보내면 사용자가 누르지도 않은 질문에 시간당 한도가
깎이고, 문장을 고칠 기회도 없어진다. 입력칸에 채워 두고 보낼지는 사람이 정한다.

질문은 노트에 실제로 있는 값으로만 만든다 — 단지명이 없으면 지역으로 묻는다.
없는 단지명을 넣어 "그럴듯한" 질문을 지어내지 않는다.

## 3. 조용히 죽는 결함을 막는 테스트

이 판이 만든 두 길은 **보내는 쪽과 읽는 쪽이 다른 파일**에 있고 타입으로 이어져
있지 않다. 한쪽에서 파라미터 이름을 바꾸면 링크는 여전히 열리고 화면도 정상으로
보이지만 **아무것도 넘어가지 않는다** — 사람이 눈으로 볼 때까지 아무도 모른다.

`tests/unit/note-handoff-986.test.ts` 가 계약이 양쪽에 적혀 있는지 본다:
`apt`/`region` 을 워크벤치가 읽는지, `q` 를 AgentChat 이 읽는지, 그리고 **q 를 읽는
자리에서 전송하지 않는지**(한도 보호가 코드에 남아 있는지).
