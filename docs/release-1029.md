### 화면
- **`/redevelopment` 새 칸 "서울시 도시계획 결정 조서"**(지도 칸 아래): 종류 칩(전체·정비사업·도시개발사업·지구단위계획) · 구 칩(건수 표시, 가로 스크롤) · 표(결정일 · 구분 · 구역 · 위치 · 면적 · 조서). 첫 목록은 서버가 최근 순 20건을 넘기고, 칩을 바꾸면 `/api/seoul/upis`(CDN 하루 캐시)에서 60건. 표가 비어 있으면(크론이 돌기 전) 칸을 내지 않는다. 출처 한 줄: "서울 열린데이터광장 · 도시계획 결정 조서 · 매일 갱신 · 원문 그대로 · 참고용(법적 효력 없음) · 결정일 = 고시 코드 기준".
- **`/redevelopment/[구역]` 새 칸 "도시계획 결정 이력"**: 구역 이름 줄기(예: "은마아파트")로 같은 구의 정비사업 조서를 찾아 결정일·조서 유형·구분·면적을 최근 순으로. 결정고시가 쌓이면 고시번호·기관·제목을 함께. 서울 밖 구역이거나 못 찾으면 칸을 내지 않는다(없다고 말하지 않는다 — 이름 표기가 다를 수 있다).
- **`/region/[서울 구]` 새 칸 "○○구 도시계획 결정 조서 · 서울시 N건"**: 정비사업·도시개발·지구단위계획 세 칸 + "조서 보기 ›"(그 구가 골라진 `/redevelopment?gu=○○구#seoul-plan`). 0건이면 칸이 빠진다.
- 데이터 출처 안내(`/data-sources`)에 "서울시 도시계획 결정 조서" 항목 추가 · 관리자 신선도 표의 정비사업 줄이 새 표(`seoul_upis_records`, 48시간 기준)를 본다.

### 적재

- 구 판별(`lib/seoul/upis.ts`): 조서 코드 앞 5자리(11680 = 강남구) → 지자체 칸 "○○구" → 위치명·지역명 안의 "○○구" → 셋 다 없으면 비움(태평로2가 같은 도심 조서). 예전 지도 어댑터(`lib/seoul/adapters/upis-rebuild.ts`)는 구 이름 줄기로 구역 이름을 찾아 "관악구 강남아파트"를 강남구로 셌다 — 같은 함수로 고쳤다(운영 캐시 26행 중 2행이 관악구로 바로잡힌다).
- `lib/redevelopment/ingest.ts`(옛 적재기) 삭제 · `scripts/validate-env.mjs` 의 `SEOUL_DATA_API_KEY` 설명을 새 용도로.

### DB — `supabase/migrations/20261003162238_1029_seoul_upis_records.sql`(운영 적용 완료)
- `seoul_upis_records`(조서) · `seoul_upis_announcements`(결정고시) · `seoul_upis_sync`(진행 상태 · service_role 전용) · 뷰 `seoul_upis_gu_summary`(구별·서비스별 건수 · security_invoker). RLS 켜짐 · 쓰기 정책 없음(크론의 service_role 만 쓴다) · anon/authenticated 는 조서·고시·뷰 읽기만. 개인정보 없음.

- 원인 추정: MCP 가 쿼리 글자에 `drop` 이 들어가면 "파괴적 문장" 확인을 기다리다 시간 초과한다(`drop policy if exists` 한 줄이 든 조각만 걸렸고, 같은 문장을 base64 로 감싸 넣으니 바로 됐다). 다음부터 `drop … if exists` 는 따로 보낸다.

### 효과
