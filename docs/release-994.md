# 994 — 개편 4판: 청약 매일 저장·알림 · 단지 판단 카드 · 마이 17→7 · 성능 경보 노이즈 제거

993 이 "결과값을 세우는 판" 이었다면 994 는 **매일 사실을 더 넓히고, 같은 형식을 단지 상세까지 펴고,
마이를 접는 판**이다. 993 배포 직후(2026-09-13) 실측에서 시작했다.

## 한 줄

**청약 공고·경쟁률이 매일 저장돼 기준일과 관심 지역 알림이 생겼고, 단지 상세도 AI·노트와 같은 판단 카드를
갖게 됐다. LCP 7~13초 경보는 사람이 아니라 헤드리스 크롬(표본 89%)이었다 — 걸러내니 실사용자 p75 는 0.7~1.9초.**

## 바뀐 것

### 994-1 · RUM 봇 표본 제거 (성능 경보의 진실)
- 최근 7일 LCP 표본 2,021건 중 1,806건(89%)이 단일 UA `(X11; Linux x86_64) Chrome/150`(새 헤드리스 크롬은 UA 에
  "HeadlessChrome" 이 없다) — 555개 경로를 JS 까지 실행하며 순회(로그인 475회). 그 표본이 "단지 상세 LCP 8.2s ·
  분석 7.7s · 로그인 7.8s" critical 경보를 만들었다. **실사용자(iPhone·갤럭시·Windows)의 LCP p75 는 홈 1.9s,
  나머지 0.5~1.2s** 로 정상.
- `web_vitals_reject_bots` 트리거 확장(모바일 표식 없는 X11 크롬 · lighthouse · naezipnow-e2e) + 4월부터 쌓인 같은
  UA 행 ~8,000건 삭제(마이그레이션 20260913130000, 적용 완료). 이제 CWV 경보는 사람 값만 본다.

### 994-2 · 청약 = 매일 저장되는 사실 (D4)
- 새 표 `applyhome_announcements`(공고: 접수 시작·마감·발표일·입주월·세대·주소) · `applyhome_competition`(경쟁률,
  마이그레이션 20260913140000, 적용 완료). **추가 API 호출 없이** 매일 도는 `supply-ingest` 가 같은 상세 행을 함께
  적재하고, 경쟁률은 최신 3페이지를 더 읽는다. ingest 로그 `applyhome` → `/admin/data`·`/admin/freshness`·`/data-sources`
  에 신선도 행, 48h 무소식이면 freshness-watch 경보.
- `/apply` 첫 화면에 **오늘의 청약** 띠: 앞으로 7일 접수 시작·마감 + 최근 발표 경쟁률(1순위·해당지역 우선) + **기준
  시각(마지막 적재)**. 캘린더·주간 아카이브는 저장소를 먼저 읽고(청약홈 장애 격리), 비었을 때만 라이브 폴백 — 캡션이
  어느 쪽인지 말한다.
- **관심 지역 청약 알림** 크론 `applyhome-alerts`(GH alerts 잡 편입): 관심 지역(`alert:region:*`) 시/도에 대해
  ① 새 공고 ② 오늘 접수 시작 ③ 오늘 당첨 발표 를 인앱 수신함으로(사용자당 하루 5건, 7일 중복 방지, 시군구까지 맞는
  공고 우선). 예측치는 만들지 않는다 — 원문 링크와 날짜만.
- `/apply` 곁 링크에서 보관된 Q&A 제거.

### 994-3 · 단지 상세 판단 카드
- `/complex/[id]` 의 "시장 축 요약"(숫자 4칸 + 신호 줄)을 **판단 카드**(구간 · 결론 · 투자 점수 · 핵심 숫자 3(기준일) ·
  근거 칩 · 반대 조건)로 — AI 진단(993-2)·임장노트(993-3)와 같은 형식. `lib/ai/verdict.ts` 가 같은 규칙으로 조립하고
  1.2초 예산은 그대로(못 받으면 생략).

### 994-4 · 마이 17 → 7
