# 시장 12가지 → 내집나우 7 — 구체안 (2026-09-29, 1025 에서 반영)

소유자가 고른 7개(1·3·7·8·9·11·12)를 "누가 · 무엇이 귀찮은가 · 우리 화면 · 데이터 · 돈이 되는 길 · 재는 숫자" 로 풀었다. 이미 만든 것은 **[1025 완료]**, 다음 차수는 **[다음]**, 대표님 손이 필요한 것은 **[OWNER]**. 숫자는 운영 DB 실측(2026-09-29)이며 목표는 기대치다.

## 한 줄 요약
내집나우는 "보는 앱"이 아니라 **"결정하고 움직이는 사람의 앱"** 이다. 7개 시장은 결국 두 고객으로 모인다 — ① 집을 고르는 개인(⑨ 결정 · ⑦ 비서 · ⑪ 살까 빌릴까 · ⑧ 귀찮은 확인) ② 그 개인을 상대하는 작은 사업자(③⑫ 중개사·소규모 임대인). ①이 쌓는 기록·결정이 ②의 브리핑 재료가 되고, ②가 고객에게 보내는 링크가 ①의 유입이 된다. 이것이 4사(호갱노노·네이버·당근·숨고)가 구조적으로 안 하는 순환이다.

## ⑨ 정보 대신 "결정"을 판다 → 결정 카드 `/decide` [1025 완료]
- **고객**: 후보 2~3곳 사이에서 몇 주째 못 정하는 실수요자. 호갱노노에서 30분 보고도 "그래서 어디?" 가 남는 사람.
- **귀찮음**: 단지마다 가격·전세가율·거래량·학교를 따로 보고 머릿속에서 합친다. 기준이 매번 바뀐다.
- **화면**: 후보 3열(비교 트레이·관심 단지에서 담기) → 내 기준 슬라이더 4개(가격·전세가율·거래량·학교) → "지금 기준 1순위" + 숫자 근거 3줄 → 결정 저장(살까·보류·패스·다시 보기 + 메모) → 지난 결정 목록.
- **데이터**: `/api/complex/[id]/detail`(12개월 매매 중앙값·건수·전세가율·갭) · `user_preferences` 페르소나 → 초기 가중치 · 학교는 POI 표(0행이면 축 비활성 "자료 없음" — 지어내지 않음). 점수 = 정규화 가중합(순수 함수·테스트 12건).
- **저장**: 로그인 `user_decisions`(적용 완료, service_role 전용) · 게스트 localStorage.
- **돈**: 무료. 결정 기록이 쌓이면 "결정 뒤 6개월 실거래 추적" (내 결정이 맞았나) 을 플러스 기능으로 — 기존 `requirePlan` 키만 쓴다(요금제 화면 불변).
- **재는 숫자**: 결정 저장 수/주 · 결정 → 노트 작성 전환율 · 후보 평균 수. 지금 0.
- **[다음]**: 관리비를 detail 응답에 실어 후보 카드 "—" 제거(1줄) · 결정 6개월 뒤 실거래 비교 카드 · 통근 시간 축(역 좌표 POI 뒤).

## ⑦ AI 를 "직원"처럼 판다 → AI 비서 `/my/assistant` [1025 완료]
- **고객**: 관심 단지를 6곳 담아 두고 잊어버리는 사람(실측: 관심 단지 6건 · 수신함 227건이 쌓여 있지만 "비서가 일했다"는 화면이 없었다).
- **귀찮음**: 매일 실거래를 들여다볼 시간이 없다. 알림은 오는데 무슨 뜻인지 모른다.
- **화면**: "이번 주 한 일" 4칸(새 실거래 알림·가격 변동·저장 검색 매치·주간 브리핑) → 다음 할 일(임장 일정 등록·D-day, 계약 D-day) → 비서가 지켜보는 것(관심 단지·저장 검색·알림 채널 상태) → 대화 열기(AgentChat).
- **데이터**: 이미 돌고 있는 크론 4개(price-alerts·watchlist-new-tx·saved-search·weekly-digest, 매일 15:00 KST)의 수신함 행을 제목으로 분류(테스트가 제목 리터럴을 잠금) · `inspection_schedules`(UI 가 없던 표에 처음 폼이 붙음) · journey 계약 일정.
- **돈**: 무료 층 = 수신함. 플러스 = 실시간 알림(`notification_realtime` 이미 플랜 키 존재)·AI 대화 한도. 비서 화면은 그 차이를 사실로 보여 주는 자리다.
- **재는 숫자**: 비서 화면 주간 방문자 · 일정 등록 수 · 알림 → 클릭률. 지금 0.
- **[다음]**: 일정 하루 전 수신함 알림 크론 · "이 단지 이번 주 요약" 한 문장 생성(실거래 기준) · 비서가 먼저 묻는 질문 1개("○○ 신고가 났어요, 결정 카드 갱신할까요?").

## ⑪ 소유보다 "빌려 쓰는" 시장 → 살까, 빌릴까 `/calculator/rent-vs-buy` [1025 완료]
- **고객**: 전세 만기 앞두고 "이참에 살까" 고민하는 사람 · 월세 사는 1인 가구.
- **귀찮음**: 매매는 이자·취득세·중개보수·기회비용, 전세는 대출 이자, 월세는 합계 — 한 번에 비교해 주는 곳이 없다(직방·다방은 호가만, 은행 계산기는 대출만).
- **화면**: 단지 검색(실거래 12개월 매매·전세·월세 중앙값 자동 입력) 또는 직접 입력 → 결과 3열(5년 총비용 + 구성 막대) → 한 줄 결론 + 손익분기 상승률 → 민감도 표(−2/0/2/4%) → 가정 목록(전부 사실 줄).
- **데이터**: `market_transactions` 중앙값 · 금리는 공시 로더(finlife) 대표값 — 없으면 빈칸 · 취득세·중개보수는 기존 `lib/finance` 산식. 원리금균등 이자분 폐형식·이분법 손익분기(테스트 5건).
- **돈**: 무료. 1024 의 `/rent`(원룸·오피스텔 신고 월세)와 짝 — "빌리는 쪽" 트래픽을 처음 받는 입구. 월세 실거래가 들어오면(**[OWNER]** API 활용신청) 월세 칸이 자동으로 채워진다.
- **재는 숫자**: 계산 실행 수 · 단지 검색 비율 · 결과 → 단지 상세 이동률.
- **[다음]**: 양도세·보유세 옵션 · 결과 공유 카드 · 결정 카드에 "살까/빌릴까" 결과 붙이기.

## ⑧ 귀찮은 일을 대신해 준다 → 계약 전 자동 확인(`/journey/contract` 안) [1025 완료]
- **고객**: 계약 앞둔 사람. 지금 일정표는 "등기부 열람·건축물대장 확인" 을 링크와 체크로만 안내했다.
- **귀찮음**: 정부24·건축HUB·인터넷등기소를 따로 들어가 단지 이름으로 찾는 일.
- **화면**: 단지 선택 → 건축HUB 기본개요 자동 조회(건물명·주용도·사용승인일·세대수·층수·연면적 — 응답에 있는 칸만) → 위반건축물은 기본개요에 없어 정부24 표제부 안내(사실) → 인터넷등기소·`/safety` 자가진단 링크.
- **데이터**: 기존 `/api/building/registry`(건축HUB). 법정동 코드가 단지 레코드에 없어 수동 입력 칸(선택)을 뒀다.
- **돈**: 무료. 이 화면이 "계약 앞둔 사람" 을 잡는다 — 그 다음이 중개사(③⑫).
- **[다음]**: 표제부 API(`getBrTitleInfo`) 연결로 위반건축물 자동 · 단지 → 법정동 코드 매핑 표 · 등기부는 공공 API 가 없어 **자동 불가**(사실) — 대신 "등기부에서 볼 것 체크리스트"를 노트 템플릿으로.

## ③ 소비자가 아닌 기업의 지갑 + ⑫ 작은 사업자의 귀찮은 일 → 중개사 브리핑 리포트 `/complex/[id]/brief` + `/pro` [1025 완료]
- **고객**: 공인중개사(전국 11만 개 사무소 — 대부분 1~2인) · 소규모 임대인.
- **귀찮음**: 고객에게 보낼 "이 단지 근거 자료" 를 매번 캡처·엑셀로 만든다. 호갱노노 캡처는 자기 이름이 안 들어가고, 네이버는 매물만 있다.
- **화면**: 단지 한 장(개요 8칸 · 타입별 최근 실거래 표 · 전세가율·갭 · 관리비·학교 · 주의: 해제 신고 N건·기준일) + 발행자 줄(사무소명·담당자·연락처 — 브라우저에만 저장, URL 에 안 실림) + "PDF 로 저장(인쇄)" + "링크 복사". `/pro` 는 입구(브리핑·위젯·알림 + 문의 폼).
- **데이터**: 단지 상세 v2 와 같은 로더(1024) · 해제 행 포함 로더(1025 #8).
- **돈**: 지금은 무료·베타(문구 그대로). 수익화 순서 — ① 사무소 로고·QR 브랜딩(플러스, `pdf_export`/브랜딩 부품은 이미 `lib/inspection/pdf-branding.ts` 에 있다) ② 월 N장 상한 → 엔터프라이즈(`bulk_pdf` 키 존재) ③ 브리핑에 사무소 매물 1건 첨부(광고가 아니라 중개사 본인 물건). 요금제 화면은 손대지 않고 기능 키만 붙인다.
- **재는 숫자**: 브리핑 인쇄 수 · 사무소 정보 입력 수(=중개사 수) · `/pro` 문의 수 · 브리핑 링크 유입(utm). 지금 0.
- **[다음]**: QR(순수 SVG) · 사무소 로고 · 브리핑 열람 수 카운트(중개사가 "고객이 봤나" 를 안다 — 이것이 재방문 이유) · 임대인용 "내 물건 시세 추적 카드"(관심 단지 + 계약 만기 알림).

## ① 오래된 산업을 디지털로 바꾼다 → 임장 자체 [코어 · 추가 없음]
- 임장(현장 답사)은 아직 종이·카톡·사진첩이다. 임장노트(작성 3단계·퀵 기록·회차 비교·AI 정리)가 그 디지털화이고, 1023 까지 워크플로는 갖춰졌다. 남은 건 사람(작성자 1명 → 6명, 전략 v2 4주 표).
- ⑫와 이어지는 확장 **[다음]**: 중개사가 고객과 **동행 임장** 할 때 노트 링크를 미리 보내는 흐름(브리핑 리포트 + 빈칸 노트 = 현장에서 채우는 한 장).

```
개인: 결정 카드(⑨) ← 살까 빌릴까(⑪) ← 계약 전 확인(⑧) ← AI 비서(⑦)가 매주 상기

        ▼
사업자: 브리핑 리포트(③⑫)가 그 단지 데이터를 고객에게 보냄 → 링크 유입 → 개인 가입 → 다시 위로
```
