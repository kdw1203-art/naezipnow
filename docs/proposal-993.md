## 결정 (이 판에서 한다)

### 993-1 매일 사실 자동 갱신
1. 단지 API **V4/V5 로 교체** + 필드명 변화에 견디는 파싱 + 실패 시 응답 키를 로그에 남기는 진단.
2. 이중 스케줄 제거(pg_cron billing-renewals · GH apt-master). 법원경매 스텁은 신선도 표·출처 페이지에서 **"미구현"** 으로 정직하게.
3. 감시 확장: 알림 스윕(plan-expiry·points-expiry)이 36시간 비면 `ops.record_health_alerts` 가 잡는다 → 관리자 화면·경보 메일.
4. 빌드 게이트(validate-env)가 파이프라인 키 18종의 **부재를 이름으로** 경고. 문서의 `INGEST_SECRET` 오류 정정.
5. 소유자 키 목록: KOSIS · 서울열린데이터 · POI 표준데이터. 청약 경쟁률 저장은 994(D4).

### 993-2 AI 분석 = 판단 카드
- `lib/ai/verdict.ts`(순수): 구간(4) · 한 줄 결론 · **대표 수치 1개** · 핵심 숫자 3개(각각 기준일·출처) · 근거 칩 · 반대 조건 · 다음 행동 1. 새 수치를 지어내지 않는다 — 이미 있는 판정만 조립.
- `/api/ai/context` 가 `verdict` 를 함께 돌려주고, `/api/ai/analysis` 의 headline/score 가 여기서 나온다(항상 null 종료).
- 화면: **결과 먼저**. 모바일은 실행 후 입력을 한 줄 요약으로 접고 결과로 스크롤, 데스크톱은 입력 좌 380px · 결과 우. 마크다운 본문은 "자세한 해석" 접힘. 근거 칩은 첫 화면에.
- 12 → 4 핵심(진단·예측·타이밍·임장 동선) 전면, 8종은 칩 한 줄로 보이게. 계약 도구 이중 피커·의미 없는 공통 입력 제거.

### 993-3 임장노트 = 판단 카드 우선
