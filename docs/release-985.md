## 1. 17 — 이미 받아 온 데이터를 화면이 쓴다

위치를 고르면 폼이 `/api/inspection/public-data-context` 를 부른다. 그 응답에는
이미 이런 게 들어 있었다:

```
marketHint       한국부동산원·KB 기준 한 줄 시세 요약
market           구조화 시세 (㎡당 매매·전세가율·거래건수·매수우위)
airQualityHint   미세먼지
checklistHints   실데이터에서 파생된 "이 지역에서 특히 볼 것"
plans            개발계획·정비사업·공원·어린이집 슬라이스
```

폼은 이 중 **`weatherHint` 하나만** 읽고 나머지를 버렸다. 요청도 캐시도 이미
쓰고 있었으니 비용은 그대로 내면서 화면에만 안 쓴 셈이다.
(981에서 겪은 것과 같은 모양 — 엔진이 읽는 입력을 UI 가 안 물어봤다.)

**새 요청 없이** 1단계에 "지금 이 지역은" 카드를 세웠다: 시세 한 줄 · 공기질 ·
지역 체크 힌트 칩 · 주변 공개 계획 건수 · 조회 날짜.

왜 작성 화면인가: 임장노트의 가장 약한 고리는 "비싸다/싸다"를 근거 없이 적는
것이다. 지금 이 지역의 실제 시세가 옆에 있으면 같은 문장이 판단이 된다.

지킨 것:
- **값을 메모에 자동으로 넣지 않는다.** 시스템이 쓴 문장이 사용자의 관찰처럼
  보이면 안 된다. 읽을 것만 준다.
- **날씨는 이 카드에 안 넣는다.** 방문 정보 칸에 이미 "제안 · …(탭하여 적용)"이
  있어서, 여기 또 적으면 같은 말이 한 화면에서 두 번 읽힌다.
- **아무것도 없으면 카드 자체가 안 뜬다.** 빈 카드는 "조회했는데 없다"를
  "볼 게 없다"로 보이게 한다.
- **건수 0 인 개발계획 슬라이스는 싣지 않는다.** 화면이 실제보다 풍부해 보인다.
- 판정은 `lib/inspection/field-brief.ts` — 단위 테스트 9건.

## 2. 11 — 파서를 하나 더 만들려다 되돌렸다

촬영 시각 파서를 새로 쓰기 시작했는데, 이미 `lib/client/exif-datetime.ts`
(`[#134]`)가 같은 일을 하고 있었다 — 리사이즈(canvas 재인코딩)가 EXIF 를 지우기
전에 원본에서 DateTimeOriginal 을 읽고, 방문일을 채우고, 사용자가 날짜를 건드린
뒤에는 덮지 않는다. 새 파일을 지우고 **이 파일을 단단하게 만드는 쪽**으로 돌렸다.
같은 일을 하는 코드가 둘이면 다음에 한쪽만 고쳐진다.

고친 것 둘 — 둘 다 테스트로 증명했다:

1. **있을 수 없는 날짜를 통과시켰다.** `Date.parse("2026-02-30T10:00:00")` 은
   NaN 이 아니라 **3월 2일로 굴러간다**(테스트에서 먼저 증명한다). 카메라 시계가
   틀어져 그런 값이 오면 방문일 `<input type="date">` 가 조용히 비었다.
   이제 구성요소가 그대로 돌아오는지 직접 확인한다. 윤년(2028-02-29)은 통과,
   평년 2월 29일은 거른다. 1990년 이전·2200년 이후도 거른다.
2. **손상된 IFD 의 항목 수를 그대로 믿었다.** 최대 65,535번 돌았고, 범위 밖
   읽기가 예외를 던져 try/catch 가 받는 구조였다. 애초에 돌 이유가 없다.

`[#134]` 이후 처음 붙는 테스트다 — 실제 JPEG 바이트를 조립해 리틀·빅엔디안,
DateTime 폴백, PNG·잘린 파일·길이 과장 같은 쓰레기 입력을 확인한다. 이 파서의
계약은 "어떤 바이트가 와도 던지지 않고, 없는 값을 만들지 않는다"다.

## 3. 15 — 죽어 있던 오프라인 큐를 연결했다

예전 오프라인 배너는 **"사진 업로드는 연결 후에 해주세요"** 라고 말했다. 현장은
지하 주차장·엘리베이터·신도시라 신호가 없는 순간이 많은데, 사진은 바로 그때
찍는다. 나중에 다시 찍을 수 없는 것을 "연결 후에"로 미루면 기록이 사라진다.

`lib/inspection/offline-queue.ts`(IndexedDB, 124줄)가 저장소에 있었는데
**아무도 import 하지 않는 죽은 코드**였다. 새로 만들지 않고 그것을 연결했다.

- 오프라인에서 사진을 담으면 **리사이즈까지 끝난 파일**을 IndexedDB 에 넣는다
  (연결 복귀 때 다시 줄이지 않는다).
- 화면에 "이 기기에 담아 둔 사진 N장"을 띄운다 — 조용히 들고 있으면 사라진 줄 안다.
  자동 업로드는 `online` 이벤트가 하지만 그 이벤트를 못 받는 경우(탭 복귀·절전)가
  있어 **"지금 올리기"** 버튼도 남긴다.
- 업로드는 기존 `uploadOne` 을 그대로 쓴다 — 경로가 둘이면 한쪽만 고쳐진다.
- **성공한 항목만 큐에서 지운다.** 실패는 남겨 다시 시도한다. 파일이 없는 항목은
  되살릴 수 없으니 지운다(큐에 영원히 남게 두지 않는다).
- 낡은 배너 문구를 고쳤다. 문구가 낡은 채 남으면 사용자는 할 수 있는 일을 안 한다.

### 실측에서 잡은 버그 둘

**① 같은 사진이 두 번 올라갔다.** 연결 복귀 이벤트가 두 번 오면(브라우저 `online`
+ 앱 재시도) 두 호출이 **둘 다** 가드를 통과했다 — 가드를 `useState` 로 뒀는데
`setState` 가 비동기라 첫 호출이 아직 `false` 를 보고 있었다. 실측: 업로드 호출
**2회**, 노트에 사진 두 장. `ref` 로 바꿔 동기적으로 막는다. 회귀 테스트로
`online` 을 일부러 두 번 던져 호출이 1회임을 확인했다.

**② 잘된 일을 실패처럼 알렸다.** "이 기기에 담아 뒀어요"를 `setSaveError` 로
띄웠더니 저장 바가 그 문장을 **빨간 `role="alert"`** 으로 내고 버튼을
**"다시 시도"** 로 바꿨다(스크린샷 확인). 담긴 사실은 큐 안내가 이미 말하므로,
오류 채널에서는 **진짜 실패**(담아 둘 수조차 없음)만 남겼다.

## 4. 같이 치운 것

`lib/inspection/offline-draft-store.ts`(45줄) **삭제**. import 하는 곳이 0이고,
폼은 자체 임시저장(`#45`, localStorage 1초 디바운스)을 쓴다. 초안 저장소가 둘이면
다음에 누가 약한 쪽을 다시 쓴다.

## 5. 번들 — 예산을 올리지 않았다

`/notes/new` 예산은 470KB 이고 시작이 463KB 였다. 세 기능을 얹으며 두 번 넘겼다
(471KB → 472KB). 둘 다 **예산이 아니라 코드를 옮겨** 해결했다:

- 현장 브리핑 카드 + 판정 모듈 → `next/dynamic` (위치를 고른 뒤에만 내려온다)
- 오프라인 큐(IndexedDB) → 동적 `import()` (오프라인일 때만)
- AI 초안 패널 → `next/dynamic` ("AI 초안 받기"를 누르기 전에는 필요 없다)

최종 **468KB / 470KB**.
