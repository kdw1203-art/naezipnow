# 1076 — 회원가입 노출 · 자동 로그인(로그인 유지) 켜고 끄기

소유자 2026-10-18: "내집나우 접속하면 관리자페이지로 자동로그인되도록 되어 있는 거 아니지? 회원가입이 잘 보이도록 해주고
자동로그인도 할 수 있도록 해줘".
DB 변경 없음 · 가격·심사 문구 변경 없음.

## 확인한 사실

- **관리자 화면은 방문만으로 열리지 않는다.** `app/admin/layout.tsx` 는 세션이 없으면 `/login?callbackUrl=/admin`, 세션은 있으나
  관리자 역할(JWT role · `STAFF_ROLE_MAP` 환경 변수 · 허용 목록)이 아니면 `/` 로 보낸다. 엣지 가드(`lib/auth/edge-login-guard.ts`)도
  세션 쿠키가 없으면 함수까지 가지 않고 `/login` 으로 302. 소유자 브라우저에서 바로 열리는 것은 그 브라우저에 **소유자 자신의**
  세션 쿠키가 있기 때문이다 — 다른 사람은 로그인 화면을 본다.
- **로그인은 이미 30일 유지된다.** Auth.js 세션 쿠키는 `Expires` 가 붙는 영구 쿠키(로컬 실측 2026-10-18: Expires = 로그인 + 30일,
  하루마다 연장). 브라우저를 닫았다 열어도 로그인이 풀리지 않는다. 그래서 "자동 로그인"은 새로 만드는 기능이 아니라 **켜고 끌 수 있게**
  보이는 일이다(공용 PC 에서는 끄고 싶다).

## 자동 로그인 끔은 어떻게 동작하나(lib/auth/keep-login.ts)

Auth.js 는 로그인마다 쿠키 수명을 달리 줄 수 없다(`session.maxAge` 는 전역). 대신 두 쿠키로 "브라우저를 닫았다"를 안다.

- 로그인 직전(비밀번호 · 구글 · 카카오 · 토스 모두) 체크 상태를 쿠키로 적는다 — 켬: 아무것도 심지 않음(nz_keep 삭제) ·
  끔: `nz_keep=0`(30일) + `nz_sess=1`(Max-Age 없는 브라우저 세션 쿠키 — 닫으면 사라진다).
- 미들웨어(문서 GET/HEAD)는 [세션 쿠키 있음 · nz_keep=0 · nz_sess 없음] 이면 세션 쿠키(조각 포함)·nz_keep·nz_authed 를 지우고
  **같은 주소로 302** — 두 번째 요청은 비회원이고, /my 류면 평소 가드가 /login 으로 보낸다. nz_keep 을 같이 지우므로 세션 쿠키 삭제가
  안 먹는 경우에도 되돌이표는 없다. `__Secure-` 이름은 Secure 속성으로 지운다(없으면 브라우저가 버린다).
- 같은 브라우저 세션 안에서는 nz_sess 가 있으니 아무 일도 없다. 크롬 "이전 세션 이어서 열기" 설정은 세션 쿠키를 되살리므로 그 설정에서는
  닫아도 유지된다 — 모든 사이트의 "로그인 유지 끄기"가 같다.
