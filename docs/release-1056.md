## 1. 출석 · 미션 · 포인트 사실 — 9가지

근거: 출석 API 는 "7일 안 가장 최근 행의 streak" 를 그대로 연속 출석일로 내려보냈다. 4일 전 출석한 사람도 "연속 출석 N일 · 오늘 이어가기"를 보고 눌렀는데
결과는 1일 — 끊긴 기록을 이어지는 것처럼 말했다. 완주 보너스 200P 는 마이 홈과 미션 센터가 **서로 다른 세 항목**으로 같은 보상을 청구했다.

1. 연속 출석 — 최근 출석이 오늘·어제일 때만 유효한 스트릭, 아니면 0(끊김). 순수 규칙 `lib/points/attendance-rules.ts`(currentStreak) · 홈 카드도 같은 API 라 함께 바로잡힘.
2. 출석 단추 "+10P" 고정 — 3일째 20P·7일째 50P 인데 늘 "+10P". GET/POST 가 `nextReward` 를 내려보내고 단추는 "출석 체크 +20P", 줄은 "연속 출석 2일 · 오늘 20P" / 출석 뒤 "연속 출석 3일 · 내일 20P", 결과 "+20P 적립 · 연속 3일 보너스 포함". 끊긴 사람에겐 "마지막 출석 10/7 · 오늘 10P"(lastDate).
3. 시작 3미션 ≠ 마이 홈 3스텝 — 미션 센터(관심 단지·키워드 알림·노트)와 마이 홈(관심 담기/지역 알림·첫 노트·공개 노트)이 같은 onboarding_complete 200P 를 각자 지급. 먼저 끝난 쪽이 받고 다른 쪽은 미완인데도 "적립 완료". → 미션 센터가 마이 홈과 **같은 질의**(verify.ts)를 쓴다: "관심 단지 또는 지역 알림 1개 · 첫 임장노트 1편 · 임장노트 1편 공개". 청구는 같은 멱등 함수.
4. 주간 미션 "관심 단지 2곳" 이 지역 알림 구독(`alert:region:*` 행)까지 셌다 → 제외.
5. 적립 방법 표 — 보관된 체크리스트 공유(template_used)와 중개사 전용 매물 적립이 모두에게 보였다 → template_used 숨김 · listing_* 는 인증 중개사에게만 "공인중개사 매물 적립" 묶음.
6. 출석 리마인드 크론 `today` 가 UTC(출석 기록은 KST) → KST. 설정·다이제스트 문구의 "매일 18:00 KST"·"월요일 저녁" — 실제 실행은 GitHub Actions 06:00 UTC = **15:00 KST** → "매일 오후(15시쯤)". 주간 다이제스트 "기본 꺼짐" 주석·문구 → 기본 켜짐(코드 기본값 true).
7. 실거래가 게임(/quiz) 하루 1회 적립 — 기록이 브라우저에만 있고 포인트가 없었다. POST /api/quiz/complete(세션 필요 · 정수·범위 검증 · 분당 10회) → `quiz_daily` 10P(한국 날짜 refId 로 하루 1회 멱등). 결과 카드 "+10P 적립" / "오늘 적립 완료" / 비회원 "로그인하면 하루 10P 적립".
8. 친구 초대 성사가 무음 — 추천인 수신함 "친구 초대 성사 · +300P"(링크 /my/points?tab=referral) · 새 회원 토스트 "초대 코드 적용 · +300P"(실지급 0 이면 포인트 미표기).
9. 미션 청구 실패 사유 — "오늘 적립 상한 도달 / 이미 적립됨 / 적립 실패 · 잠시 후 다시" 로 구분. "✓" 기호 접두 제거.

## 2. 참여 알림 — 상대에게 닿지 않던 행동 9가지

근거: 좋아요·댓글 채택·후기 도움·팔로우·답글·지역 레벨 상승이 모두 **상대에게 아무 알림도 보내지 않았다**(포인트만 조용히 들어감). 설정 화면의
"댓글·좋아요·전문가" 푸시 스위치 6개는 **읽는 발송자가 레포에 0개**였다. 공개 프로필 /u/[handle] 로 들어오는 링크는 사이트 안에 0개.

10. 글 좋아요 — 1·5·10·25·50·100개에 닿을 때 작성자에게 "좋아요 N · 글 제목 · 날짜"(본인 제외 · 취소 제외). 공통 헬퍼 `lib/notifications/engagement-notify.ts`.
11. 댓글 채택 — 채택된 댓글 작성자에게 "댓글 채택 · 글 제목 · +30P"(실지급 0 이면 포인트 생략), 링크는 그 글의 댓글 자리.
12. 단지 후기 도움 — 1·5·10·25 에 닿을 때 "후기 도움 N · 단지명 후기 · 날짜", 링크는 단지 화면(정규 슬러그). 후기 저장 문구 "후기가 등록됐어요. 이웃에게 큰 도움이 됩니다"(0P 여도 30P 안내) → "후기 저장 · +30P" / "후기 저장".
13. 새 팔로워 — 새 팔로우일 때만(재클릭 제외) "새 팔로워 · 닉네임 · 날짜", 링크 /u/{handle}.
14. 임장노트 답글 — 부모 댓글 작성자에게 "내 댓글에 답글 · 노트 제목 · 작성자"(소유자·본인 제외). 소유자 알림은 그대로.
15. 지역 임장 레벨 상승 — 50P 가 실제 지급될 때 "지역 임장 레벨 상승 · {지역} {레벨} · +50P".
16. 설정 스위치 배선 — pushLikes → 좋아요·후기 도움·팔로워 푸시 · pushComments → 노트 댓글/답글·동네 글 댓글·채택 푸시 · pushExpert → 전문가 답변 푸시(상담 답변 라우트가 헬퍼를 거친다). 설정 조회 실패 시 푸시만 생략(인앱은 남음). emailLikes·emailExpert 는 메일 발송자 자체가 없어 다음 묶음의 제거 후보.
17. 작성자 이름 → 공개 프로필 — 노트 상세·이야기 상세·동네 토론의 작성자 이름이 /u/{이름} 링크(익명·마스킹·편집부·이메일 모양은 글자 그대로 — `lib/profile/author-href.ts`). 뉴스 상세는 자동수집 기사라 제외.
18. 받은편지함 분류 — 새 제목(답글·채택·팔로워·후기 도움·레벨 상승)이 매물 탭으로 새지 않게 활동 낱말을 먼저 본다.
