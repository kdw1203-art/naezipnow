# 1003 — 토스페이먼츠 "홈페이지 변경(→ naezipnow.com)" 2차 반려 분석과 보완

2차 반려 통지(상점관리자 MID 정보 배너, 문구는 1차와 동일):
**"변경 원하시는 홈페이지 내 결제수단 신용/체크카드가 확인되지 않습니다. 결제창 연동 가능 여부 확인 부탁드립니다."**
MID `nuguzibowg`(계약완료) · 등록 홈페이지 `https://nuguzip.com` → 바꾸려는 주소 `https://naezipnow.com`.

## 1. 1001 은 무엇을 놓쳤나 — 심사자 동선 실측

1001(2026-09-14 배포)은 비회원 주간권 결제를 열었다. 그런데 **운영에서 한 번도 쓰이지 않았다.**
근거 둘, 모두 운영 DB 실측(2026-09-17):

| 사실 | 값 | 읽는 법 |
|---|---|---|
| `page_view_events` 2026-09-16 13:57 KST 한 세션 | `/` → `/subscription`(13.5초) → `/` 뒤 이탈 | 요금제 화면까지 왔다 |
| 같은 기간 `/subscription/checkout` 페이지뷰 | **0건** | 체크아웃 화면에는 오지 않았다 |
| `payments` 주문 | 2026-09-11 이후 **0건** | 결제창을 연 사람이 아무도 없다 |

즉 심사자는 **요금제 화면에서 결제창까지 가는 길을 못 찾았다.** 1001 이 만든 길은 실재했지만
다음 세 겹에 가려져 있었다.

1. **헤더(GNB)에 결제 진입로가 없었다.** 대분류는 임장노트·지도·AI 분석·동네 넷뿐이고, 요금제는 푸터 한 줄("구독 안내")뿐이었다.
2. **요금제 화면의 1순위 버튼이 2단계 확인이었다.** "플러스 시작하기"를 누르면 버튼이 "월간 결제창으로 이동합니다 / 취소 / 계속"으로 바뀐다 — 한 번 눌러서는 아무 일도 일어나지 않는 것처럼 보인다(이동 페이지뷰가 0인 것과 일치).
3. **결제창 앞에 이메일 입력을 세워 뒀다.** 1001 의 비회원 결제는 "이메일을 적어야" 주문이 만들어졌다. 심사자는 상품을 사러 온 사람이 아니라 **결제창이 열리는지 확인하러 온 사람**이다.

## 2. 1003 보완 — 타이핑 0, 클릭 1~2번으로 카드 결제창

| 경로 | 클릭 |
|---|---|
| `/` → GNB **요금제** 호버 → **주간권 카드 결제** → 체크아웃 → **1,100원 카드로 결제하기** | 2 |
| `/` → GNB 요금제 → `/subscription` → **카드로 1,100원 결제하기 (7일 이용권)** → 체크아웃 → 결제 버튼 | 3 |
| `/subscription/payment-methods` → **지금 카드 결제창 열어보기 →** → 결제 버튼 | 2 |

- **이메일은 선택**이 됐다(`lib/payments/guest-order.ts readGuestEmailInput`). 비워 두면 `user_email = null`,
  `metadata.guest=true · claimPending=true` 주문이 만들어지고 곧바로 토스 결제창이 열린다.
- 결제가 끝나면 `/payment/success` 가 **그 자리에서** 이용권 받을 이메일을 묻는다
  (`POST /api/payments/guest-claim` — `orderId` + **`paymentKey`** 쌍이 맞아야 붙는다. 주문번호는 비밀이 아니지만
  paymentKey 는 결제창을 통과한 브라우저에만 돌아온다). 계정이 이미 있으면 즉시 켜지고, 없으면 그 이메일로 가입하는 순간 켜진다.
- 헤더·좌측 내비·모바일 전체 메뉴에 **요금제** 대분류(요금제·이용권 / 결제 수단 안내 / 주간권 카드 결제)를 추가했다.
- `/subscription` 첫 화면에 주간권 결제 블록을 올리고, 버튼을 2단계 확인이 아닌 **링크 직행**으로 바꿨다.
- 결제수단을 글로도 적는다: "신용카드 · 체크카드 결제 (토스페이먼츠 결제창) · 카드번호는 내집나우 서버에 저장되지 않습니다".

### 로컬 실측(스텁 SDK로 호출 인자 확인)
비로그인 상태에서 `/subscription/checkout?tier=pro&billing=weekly` 의 결제 버튼을 **이메일 없이** 누르면:

```
POST /api/payments/toss/create → 200 {"orderId":"WOODONG-…","amount":1100,"guest":true}
requestPayment({ method:"CARD", amount:{currency:"KRW",value:1100}, orderId:"WOODONG-…",
                 orderName:"내집나우 플러스 주간권 (7일 · 단건)",
                 successUrl:".../payment/success", failUrl:".../payment/fail" })  customerKey: ANONYMOUS
```
운영 키는 결제창형(`live_ck_…`)이라 이 호출이 곧 **신용/체크카드 결제창**이다.

## 3. 소유자 재신청 절차

1. 1003 배포 뒤 **시크릿 창**에서 한 번 확인한다(결제는 취소해도 된다):
   `https://naezipnow.com/subscription` → "카드로 1,100원 결제하기 (7일 이용권)" → "1,100원 카드로 결제하기" → 토스 카드 결제창이 뜨는지.
2. 토스 상점관리자 → 내 상점 → **MID 정보 → 기본 정보 "변경"** → 홈페이지 주소 `https://naezipnow.com`.
3. 요청사항(메모)에 아래를 그대로 붙인다.

```

신용/체크카드 결제창 확인 경로 — 회원가입·로그인·이메일 입력 없이 2번의 클릭으로 열립니다.
1) https://naezipnow.com/subscription/checkout?tier=pro&billing=weekly 로 바로 접속
2) "1,100원 카드로 결제하기" 버튼 클릭 → 토스페이먼츠 신용/체크카드 결제창이 열립니다
   (상품: 플러스 주간권 7일 · 1,100원 · 1회성 단건 결제)
사이트 메뉴에서 오는 경로: 상단 메뉴 "요금제" → "주간권 카드 결제" (또는 요금제 화면 첫 화면의
"카드로 1,100원 결제하기" 버튼).
결제수단 안내: https://naezipnow.com/subscription/payment-methods

정기결제(월간 2,900원 · 연간 27,600원)는 카드 등록(빌링키) 방식이라 회원 전용입니다. 확인이 필요하시면

사업자 정보(상호 우리동네이야기 · 대표 고대웅 · 378-06-02465 · 통신판매업 2026-안양동안-1095),
이용약관·개인정보처리방침·환불규정은 모든 페이지 푸터와 https://naezipnow.com/legal/terms#refund 에 있습니다.
```
   테스트 계정 아이디·비밀번호는 소유자가 직접 채운다(채팅·코드에 적지 않는다).
4. 또 반려되면 **반려 문구를 그대로** 전달해 달라. 이번에는 심사자가 어디까지 왔는지도 같이 본다 —
   `/admin/traffic` 의 유입·페이지 흐름과 `payments` 주문 생성 여부로 "결제창을 열었는가"가 기록에 남는다.

## 4. 이번에 남는 확인점
- 결제창이 열렸는지는 이제 **주문 행**으로 증명된다(`payments.metadata.guest=true`). 다음 심사 때 주문이 0건이면
  또 화면 앞에서 멈춘 것이고, 주문이 생겼는데 반려되면 사유가 결제창 밖에 있다는 뜻이다 — 두 경우의 대응이 다르다.
- 운영 일반결제 키는 결제창형(`live_ck_…`), 빌링 키는 위젯형(`live_gck_…`)이다. 위젯 렌더가 실패해도
  주간권 결제 카드는 남기도록 고쳤다(1001 은 그 경우 로그인 버튼만 남겨 다시 벽이 됐다).
