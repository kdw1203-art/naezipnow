# 974 — 동네이야기 9칸 표시 통일 + 분석 히어로 시인성 (2026-09-07)

소유자 지시(캡처 2장): **"동네이야기 안에 있는 세부 카테고리에서 보여지는 항목들이
다른 게 있어 … 각 카테고리의 보여지는 부분에 대해 글자 등에 대해서 전체적으로 개선"**,
그리고 분석 화면 캡처와 함께 **"글씨가 안 보이는 것, 남양주시로 나올 필요가 없는데
나오는 것들"**.

972 에서 머리 **모양**은 맞췄는데, 이번에 9칸을 나란히 놓고 보니 **모양만 같고 안에
넣는 말이 제각각**이었다. 모양이 같은데 말이 다르면 그건 통일이 아니다.

## 1. 로딩 화면이 본문과 달랐다 — 소유자 캡처의 정체

캡처 1 의 `/qna` 는 브레드크럼이 "홈 › 동네이야기 › 단지 Q&A" 이고 제목이 카테고리 줄
**위**에 있었다. 지금 코드에는 그런 화면이 없다 — 그건 **로딩 스켈레톤**(`loading.tsx`)
이었다. 스켈레톤이 옛 패턴 그대로 남아 있어서, 로딩 중과 로딩 후가 서로 다른 화면처럼
보였다.

| loading.tsx | 브레드크럼(전) | 제목(전) |
|---|---|---|
| /qna | `홈 › 동네이야기 › 단지 Q&A` | 카테고리 줄 **위** |
| /apply | `홈 › 동네이야기 › 청약 센터` | 카테고리 줄 **위** |
| /auctions | `동네이야기 › 공매·경매` (본문은 "공매 물건") | 없음 |
| /supply | `홈 › 시장 › 입주 예정 물량` | "아파트 입주 예정 물량" |
| /redevelopment | `홈 › 동네이야기 › 정비사업 지도` | 카테고리 줄 **위** |

다섯 개 전부 본문과 같은 머리(카테고리 줄 + 아이콘 칩 + 제목 + 한 줄)로 바꿨다.

## 2. 같은 문장이 두 곳에 있어서 어긋났다 — 단일 출처로

문구를 `lib/town/category-links.ts` 한 곳으로 올렸다(`headSub`, `townBreadcrumb()`).
본문과 스켈레톤이 같은 값을 읽으므로 **어긋날 자리가 없다.**

세 칸의 규칙도 `TownPageHead` 주석에 못 박았다.

- **제목** = 카테고리 줄·브레드크럼의 라벨과 **같은 말**. `/supply` 는 "입주 물량"을 눌렀는데 "아파트 입주 예정 물량" 페이지가 나왔다 → "입주 물량"으로.
- **한 줄** = 명사형 "대상 — 출처·구성". 아홉 칸 중 다섯은 명사형이고 넷은 "…받아요/…찾아보세요" 권유였다. 권유는 본문 CTA 와 빈 상태가 할 말이지, 아홉 칸이 나란히 권유하면 아무 말도 안 된다.
- **오른쪽 액션** = 이 카테고리에서 할 일 하나. 뉴스에는 "자료·리포트 ›", 자료에는 "뉴스 ›" 가 있었다 — 그 이동은 **바로 위 카테고리 줄이 이미 한다**. 제거.

결과(1280px 실측): 9칸 전부 제목 = 라벨, 한 줄 = 같은 문형, 액션은 전문가·모임 둘뿐.

## 3. 카테고리 줄의 빨간 점이 페이지마다 개수가 달랐다

빨간 점은 "참여자를 모집 중인 칸"(전문가·모임·자료)인데 `humanSupplied && !pinned`
라, **보고 있는 페이지가 그 셋 중 하나면 2개, 아니면 3개**로 보였다. 같은 줄이
페이지마다 달라 보이면 그건 상태 표시가 아니라 잡음이다. 활성 여부와 무관하게
항상 3개로 두고(현재 위치는 오른쪽 위 파란 점이 따로 말한다), 뜻은 툴팁에만 있던 것을
카드 이름(`aria-label`)에 넣어 낭독기·터치 기기에서도 읽히게 했다.

## 4. Q&A 가 0 을 열네 번 찍고 있었다

질문이 한 건도 없을 때 상태 탭 "전체 0 · 답변 대기 0 · 답변 완료 0", 주제 칩 10개가
전부 "0", 그 아래 "0건". 970 · C-13 에서 전문가 화면의 "0 · 0 · —" 를 지운 것과 같은
이유로 **0 만 늘어선 필터는 지표가 아니라 빈 칸**이다. 한 건도 없고 검색·주제 필터도
없을 때는 필터 줄 전체를 감춘다(첫 질문이 올라오면 그대로 돌아온다).

## 5. 분석 히어로 — 글자가 "안 보인" 게 아니라 배경과 같은 색이었다

`/analysis/price` 실측:

| 요소 | 색 | 배경 | 대비 |
|---|---|---|---|
| 제목 | `rgb(25,31,40)` | `rgb(11,37,69)` | **1.1 : 1** |
| 설명 | `rgb(78,86,97)` | 〃 | 1.6 : 1 |
| 출처 줄 | `rgb(96,106,119)` | 〃 | 2.3 : 1 |

히어로(`.hub-hero`)의 배경은 네이비인데 안의 글자가 **라이트 테마 토큰**(ink·text-2·
text-3)이었다. KPI 칸만 멀쩡했던 건 그 칸에 흰 배경이 따로 깔려 있어서다.
on-dark 토큰으로 바꿨다 — 수정 후 제목 `rgb(246,241,231)`, **14.5 : 1**.

`ToolHero` 는 공용이라 **분석 도구 4개**(면적대별 시세·시세 타이밍·시장 온도·전세가율)
가 한 번에 고쳐진다. 색 토큰 대비 검사는 토큰 *쌍*을 보기 때문에 "라이트 토큰을 어두운
면 위에 얹은" 이 조합은 못 잡는다 — 주석으로 규칙을 못 박아 뒀다.

## 6. "남양주시" 가 한 화면에 다섯 번

설명·지역 선택기·출처 줄·오른쪽 해설·아래 링크에 모두 있었고, 출처 줄은 바로 위 KPI 가
큰 글씨로 이미 말한 "실거래 6,789건 · 245개 단지"를 한 번 더 적고 있었다.
출처 줄이 할 일은 **무엇을 근거로 셌는지** 하나다 → `2026.01~2026.08 · 국토교통부 신고
매매가 기준`.
