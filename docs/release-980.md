### 색은 눈으로 고르지 않았다

액센트 16개는 `tests/unit/tool-persona-980.test.ts` 가 **WCAG 대비를 실제로 계산**해
막는다 — 흰 바탕 위 4.5:1, 다크 표면(`#171b22`) 위 4.5:1, 그리고 **같은 hex 재사용 금지**.
(globals.css 의 `check-contrast-tokens` 는 토큰만 보므로 이 값들을 못 본다.)

색은 주제에서 나온다: 리스크는 붉고(#B91C1C), 동선은 길의 초록(#15803D),
수익률은 이익의 초록(#047857), 타이밍은 신호의 주황(#C2410C), 계약은 서류의
적갈(#9F1239). 무작위 팔레트가 아니다.

## 3. 반응 네 가지 — 소유자가 고른 항목 그대로

**① 실행 중 연출** — 도구마다 다른 몸짓 7종. 다만 **점검 자체는 같다**:
실거래 대조 / 전월세·공급 / 노트·뉴스 / 정리 — 이 네 가지 실제 점검에 붙는
설명만 도구의 말로 바뀐다. 없는 단계를 지어내지 않는다.

> 진단: "국토부 실거래 대조 — 점수의 바닥을 잡는 중"
> 예측: "국토부 실거래 대조 — 시나리오의 출발점을 잡는 중"
> 동선: "국토부 실거래 대조 — 들를 곳의 최근 시세를 확인하는 중"

진행률 바도 없다. 몇 %인지 모르면서 아는 척하지 않는다.

**② 결과 등장 방식** — 점수는 올라오고(count-up), 표는 좌→우로 펼쳐지고(sweep-lr),
동선·궤적은 그려지고(draw-path), 위험은 한 줄씩 쌓인다(stagger-rows).
`prefers-reduced-motion` 이면 전부 즉시 표시.

**③ 조작 피드백** — `.tool-scope` 안에서는 `--primary` 자체가 도구 색이다.
버튼·링크·포커스 링·칩 hover 가 전부 같은 색으로 반응한다.
(전역 `--primary` 는 건드리지 않는다. 스코프 안에서만 갈아 끼운다.)

**④ 결과에 따른 말투** — `lib/ai/outcome-band.ts` 가 구간을 정하고 도구별 문장이 뜬다.
구간은 **서버가 이미 준 판정**(레이더·시그널·플래그)만으로 정한다 — 여기서 새로
계산하는 수치는 없다.

```
strong  이 단지 리스크 점검 → "지금 잡히는 큰 위험은 없습니다. 없다는 게 아니라 안 잡혔다는 뜻이에요."
weak    이 단지 수익률 계산 → "지금 조건으로는 마이너스입니다. 어느 항목이 갉아먹는지 보세요."
thin    이 단지 매수 타이밍 → "거래가 너무 적어 신호가 서지 않습니다. 바늘을 억지로 세우지 않았어요."
```

`thin`(재료 부족)을 좋은 쪽으로 반올림하지 않는다. 단위테스트가 그것도 막는다 —
16종의 `thin` 문구에 부족을 말하는 표현이 반드시 있어야 통과한다.

한 가지 예외를 코드로 박았다: **AI 키가 없어 서술만 빠진 경우는 `thin` 이 아니다.**
그걸 데이터 부족으로 세면 규칙 계산이 멀쩡한데도 화면이 "모자랍니다"라고 말한다.

## 4. 화면 구성도 실제로 달라진다

`composition` 이 **결과 블록 순서**를 정한다.

| 아키타입 | 순서 | 이유 |
|---|---|---|
| 계기판·점수형 (gauge·dossier·calculator·allocation·trajectory·route) | 제목 → 위젯 → 본문 → 반대조건 | 눈금·점수가 본문보다 먼저 |
| 표·목록형 (matrix·atlas·console·workbook) | 제목 → **본문** → 위젯 → 반대조건 | 표가 먼저고 위젯은 보조 |
| 장부형 (ledger — 리스크·계약) | 제목 → 위젯 → **반대조건** → 본문 | 위험 목록 바로 뒤에 "이 판단이 틀리는 조건" |
