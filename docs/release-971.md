# 971 — 리포트 수수료 10% 확정 · 단지 데이터 수집 보강 (2026-09-06)

소유자 지시: **"응 10프로로 통일해주고 / 지오코딩, 단지정보에 대한 수집이 아직 한참
부족한것 같아"**

두 가지다. 앞은 값 하나를 못 박는 일이고, 뒤는 파이프라인을 고치는 일이다.

## 1. 리포트 판매 수수료 = 10%

970 은 코드가 실제로 정산하던 7% 를 단일 출처로 삼아 `/legal/fees` 의 10% 표기를
7% 로 내렸다. 소유자 확정은 **10%** 이므로 상수 하나를 되돌렸다.

| 파일 | 바뀐 것 |
|---|---|
| `lib/billing/marketplace-fees.ts` | `REPORT_SELLER_FEE_RATE = 0.10` · 인증 전문가 우대 `0.06`(기본 대비 4%p) |

이 상수 하나에서 `/legal/fees` 표, `/subscription` 비교표, 플랜 카드, 크리에이터
정산 화면(`lib/creator/sales.ts` 의 `SETTLEMENT.platformFeeRate`)이 모두 파생된다.
단위검증에 `feePct(0.1) === "10%"` 와 상수값을 함께 못 박아, 다음에 누가 한쪽만
고치면 빌드가 막힌다.

## 2. 단지 정보 — 이름이 아니라 **필지**로 잇는다

### 무엇이 부족했나 (실측)

실거래가 있는 단지 **33,182개 중 세대수가 붙은 건 9,337개(28.1%)** 였다. 지도의
세대수 슬라이더와 단지 카드가 대부분 비어 보이던 이유다.

원인은 매칭 방식이었다. 세대수를 잇던 두 매트뷰는 **공백만 지운 이름의 완전
일치**를 요구한다. 그런데 국토부와 K-apt 는 같은 단지를 다르게 부른다 —
"성호" ↔ "호원성호", "리센츠" ↔ "잠실리센츠", "공작" ↔ "공작부영2차".

게다가 이름 전국 매칭(byname)은 **지역을 안 본다**. 커버리지만 낮은 게 아니라
틀린 값이 섞여 있었다:

| 단지 | 붙어 있던 값 | 실제(K-apt 대장) |
|---|---|---|
| 의정부 호원동 "성호" | 1,728세대 | **416세대** (호원성호) |
| 서울 강동 천호동 "두산위브센티움" | 361세대 | **156세대** |
| 인천 남동 구월동 "롯데캐슬골드" | 400세대 | **3,384세대** (38개동) |

### 어떻게 고쳤나

주소는 두 원천이 같은 말을 한다. 실거래 주소는 `…동 번지` 로 끝나고 대장
`jibunAddress` 는 `시도 시군구 동 번지 이름` 이다. **같은 필지에 선 아파트는 같은
아파트다.**

새 매트뷰 `market_agg.complex_master_link` 가 (동, 번지)로 후보를 모으고
시군구 경로가 어긋나면 버린다(대장 경로가 실거래 경로로 끝나는지 본다 — 이
가드가 없으면 전국의 같은 이름 "중구·북구"가 서로 붙는다). 남은 후보에 두 단계
근거를 매긴다.

- **1차** 이름 열쇠가 한쪽이 다른 쪽을 품는다(브랜드 표기 흔들림 흡수: 아이파크/IPARK, 이편한세상/e편한세상 …) — 8,195건
- **2차** 이름은 안 걸리지만 사용승인 연도와 건축년도가 ±1년 — 2,632건

그리고 **갈리면 잇지 않는다.** 한 필지에 세대수가 다른 대장 행이 둘 이상이면
그 단지는 비운다. 주차·동수·승강기·난방·시공사는 한 단계 더 엄격하게, 후보가
**정확히 하나**일 때만 싣는다. 2026-08-10 사고("공작아파트" 패널에 공작럭키
스펙이 붙었다) 이후의 원칙 그대로 — 스펙 없는 패널이 옆 단지 스펙이 붙은
패널보다 낫다.

| 원장 version | 무엇 |

**권한은 넓히지 않았다.** 새 매트뷰는 service_role SELECT 만 받는다. 앱은 이

**중간에 낸 사고와 교훈**: `complex_households_resolved` 를 DROP 했더니
`map_complex_attrs()` 가 깨졌다. PostgreSQL 은 **함수 본문 안의 참조를 의존성으로
추적하지 않아** DROP 이 조용히 성공하고, 동적 SQL 이라 함수 생성 시점에도
검사되지 않는다. 증상은 "지도 필터를 켜면 마커가 사라진다" 라는 조용한 형태다.
적용 직후 호출해 보고 잡아 같은 세션에서 고쳤다(20260906230714). 다음부터 MV 를
지우기 전에는 `select proname from pg_proc where prosrc like '%<이름>%'` 를 먼저 돌린다.

## 3. 수집 크론 두 건 — 몇 달째 멈춰 있던 것들

### 3-1. `apt-detail-enrich` 교착 (네 행이 백필 전체를 막고 있었다)

배치는 `metadata.detailFetchedAt` 이 **없는** 행만 고른다(스탬프가 곧 커서다).
그리고 "성공 0건이면 API 장애일 수 있으니 스탬프를 찍지 않는다"는 안전장치가
있었다. 이 둘이 만나면 **상세가 영영 안 오는 행**에는 덫이 된다.

실제로 `A10019968`·`A10019969`·`A10019970`·`A10019977` 네 행만 남아,
매 실행 이 넷을 뽑고 → 전부 miss → 성공 0건 → 스탬프 없음 → 다음 실행도 같은 넷.
매일 `처리=4 병합=0 실패=4` 라는 error 로그가 하나씩 쌓였다(신선도 경보의 상수항).

- 시도 횟수(`detailAttempts`)를 세고, **3회**를 넘긴 행은 성공이 0건이어도 스탬프를 찍어 커서를 넘긴다. 사흘 연속 API 장애로 잃는 건 없다 — 아래 재시도 배치가 계속 두드리므로.
- **`retryAptDetailMissBatch` 신설** — `detailStatus='miss'` 인 1,158행을 `detailFetchedAt` 오름차순(가장 오래 안 본 것부터)으로 다시 두드린다. 다시 miss 여도 스탬프를 새로 찍어 뒤로 보내므로 어떤 행도 굶지 않는 회전문이 된다. 신규 백필이 "미보강 0건"일 때 이어서 돈다(한 실행에 하나 몫의 예산).
- 로그에서 **miss(아직 없음)와 쓰기 실패(고장)를 분리**했다. 매일 켜져 있는 빨간 줄 안에는 진짜 고장이 숨는다.

### 3-2. `apt-master-ingest` 가 "변경 0건"을 "건너뜀"으로 적던 것

`upserted`(RPC 가 실제로 바꾼 행) 만 봤기 때문에, **이미 최신이라 바꿀 게 없었다**와
**한 행도 못 읽었다**가 똑같이 `skipped` 로 기록됐다. 대장이 채워진 뒤로는 매일
같은 줄만 쌓였고, 그 사이에 **읽기 자체가 0 인 시군구**가 묻혔다.

- `fetched`(읽어서 저장 가능한 형태로 만든 행) 를 따로 센다. `읽음=N 변경=M` 으로 적고, 읽음이 0이면 `error`.
- **빈 시군구를 로그에 드러낸다** — `· 빈 시군구=30140,30170`.
- `?codes=30140,30170` 로 **특정 시군구만 즉시 재수집**할 수 있다. 순환은 한 바퀴가 9.5일이라, 빠진 지역을 발견해도 확인까지 그만큼 기다려야 했다.

> **소유자 확인 요청**: 대장에 단 한 행도 없는 시군구가 셋 있다 — **대전 중구(30140)·
> 대전 서구(30170)·울산 중구(31110)**(실거래 단지 합계 684개). 서귀포시(50130)도
> 55행뿐이다(실거래 175). 배포 뒤 아래 한 줄로 확인할 수 있다.
> `.../api/cron/apt-master-ingest?codes=30140,30170,31110,50130`
> 응답의 `fetched` 가 0 이면 공공 API 가 그 코드에 대해 빈 값을 주는 것이고,
> 0 이 아니면 순환이 그 슬라이스를 놓치고 있었던 것이다. 어느 쪽인지에 따라
> 다음 라운드에서 손댈 곳이 갈린다.

## 4. 지오코딩

현황부터: `complex_geocode` 는 **ok 32,968 · notfound 177 · 미시도 38** 로 99.4%다.
"못 찾음"을 7일 뒤 다시 보는 규칙도 이미 있다(RPC `complexes_needing_geocode`).
그래서 여기서 고칠 것은 커버리지가 아니라 **질의의 질**이었다.

- **도로명 주소를 1순위 후보로.** 네이버 지오코더는 주소 전용이고 그중 도로명을 가장 잘 읽는다. 못 찾는 177건의 상당수는 신축·택지라 실거래 지번이 `가-`·`BL-2` 같은 블록 번호여서 애초에 주소가 아니다 — 그런 단지도 대장에는 도로명이 있다(현재 notfound 중 26건 확보, 앞으로 들어오는 단지에는 더 크게 작동한다).
- **시/도 보정.** 실거래 주소는 `남구 신정동 산107-50` 처럼 시/도 없이 시작한다. "남구·중구·북구"는 전국에 여럿이라 다른 도시로 찍힐 수 있다. `region_name`("울산 남구")의 앞 토막을 빌려 붙인 후보를 원본보다 먼저 시도한다. 이건 **커버리지가 아니라 정확도** 문제다 — 조용히 틀리는 쪽이라 눈에 안 띈다.
- 후보 순서 판단을 순수 모듈 `lib/map/geocode-query.ts` 로 떼어 단위검증했다(`server-only` 모듈은 node:test 가 못 읽는다).
