## 1. 왜 "넘어가지 않는" 것처럼 보였나

코드상 흐름(마커 → `resolvePickedComplexById` → `onPick` → 라우팅)은 끊긴 데가 없다. 막히는 것은
**고를 마커가 화면에 없을 때**였고, 그게 세 가지 경우에 일어난다.

1. 서랍은 늘 **서울시청 level 6**에서 열린다. 그 자리의 한 화면 안에는 실거래 단지가 몇 곳 없다 —
   빈 지도처럼 보인다.
2. 지도 SDK 가 뜨지 않으면 `NaverMap` 은 **OSM 대체 지도**로 내려간다. 거기에는 **마커가 아예 없다.**
   그때 고를 길은 검색창 하나뿐이었다(로컬 재현 캡처로 확인).
3. 뷰포트 조회가 지도의 `onIdle` 에서만 돌았다 — 지도가 안 뜨면 조회 자체가 한 번도 돌지 않는다.

### 고친 것

- **보이는 단지를 목록으로도 준다.** 서랍 아래에 "이 화면의 단지 N곳 · 눌러서 고르기"(최대 12줄,
  이름 + 평당가). 누르면 마커와 **같은 경로**(`handleMarker` → `resolvePickedComplexById`)로 들어가
  그 도구로 넘어간다 — 조립이 한 곳이라 지도로 고르든 목록으로 고르든 결과가 같다.
- **열릴 때 한 번 미리 물어본다.** 중심·축척으로 만든 근사 경계(`approxBounds`)로 뷰포트를 한 번
  조회한다. 지도가 떠도 안 떠도 목록은 선다. 지도가 뜨면 곧 `onIdle` 이 **진짜** 경계로 덮어쓴다
  (늦게 온 응답은 `reqRef` 가 버린다).
- **지도가 안 뜨면 목록에 자리를 더 준다**(최대 높이 46% → 78%)。 빈 회색 칸을 크게 둘 이유가 없다.
- **안내 문구를 사실에 맞춘다.** 전: "지도 불러오기 실패 · 위 검색창에 단지명을 넣어 주세요."
  후(목록이 있을 때): "지도를 불러오지 못했어요 · 아래 목록이나 검색으로 고르세요".
  단지가 한 곳도 없을 때: "이 화면에는 실거래가 있는 단지 없음 · 지도를 옮기거나 위에서 검색".
