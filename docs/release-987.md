# 987 — 개성 + 바깥 피드백 정리 (마지막 판)

이 판이 덮는 것: **26 종이 노트 시각 언어 · 28 판단 가능 항목 · 29 persona(984에서 이월)**
그리고 바깥 피드백에서 나온 **신뢰 근거 페이지 · 후기 수집 장치 · 첫 노트 우선**.

---

## 1. 26 — 세 목소리를 면으로 가른다

노트 화면에는 성격이 다른 세 가지 글이 섞여 있다:

| | 누가 쓴 것 | 예전 화면 |
|---|---|---|
| ① | 사람이 현장에서 적은 것 | 카드 안의 **맨 `<p>`** |
| ② | 시스템이 계산한 것 | 흰 카드 |
| ③ | AI 가 서술한 것 | 잉크 다크 패널(`.ai-panel`) + AI 칩 + 면책 |

**③만 제 면을 갖고 있었다.** 화면이 "AI 는 특별하고 당신이 쓴 건 특별하지 않다"고
말하는 셈이었다 — 이 제품에서 제일 귀한 건 ①인데.

①에 **종이 면**을 준다(`.note-paper`): 한지 톤 + 줄괘선 + 왼쪽 여백선, 현장 노트의
모양이다. 장식이 아니라 **읽는 사람이 출처를 눈으로 가르게 하는 장치**다 —
종이 위 글은 다녀온 사람이 쓴 것, 어두운 패널은 AI 가 쓴 것, 흰 카드는 계산한 것.

만들며 지킨 것:
- **줄괘선을 `line-height` 에 맞춘다**(1.7 × 13px ≈ 22px). 어긋나면 글자가 줄 위에
  떠 보여 오히려 지저분해진다. 실측 스크린샷으로 글자가 줄에 앉는지 확인했다.
- **다크에서 같은 구조가 유지된다.** `--brand-hanji` 가 이미 웜 다크(#262119)로
  뒤집히는 토큰이라, 색을 새로 정하지 않고 토큰을 그대로 쓴다. 대비 게이트 통과.
- **인쇄에서는 괘선을 뺀다.** 잉크만 먹고 읽기는 나빠진다.

## 2. 28 — 상/중/하가 무엇인지 밝힌다

항목 평가(채광·소음·주차·교통)가 등급처럼 보이면 **측정값으로 읽힌다.** 실제로는
다녀온 사람의 인상이다. 한 줄을 붙였다:

> 다녀온 사람이 그 자리에서 느낀 인상이에요 — 측정값이 아닙니다.

확인할 수 있는 것(실거래·공표 통계)은 986에서 붙인 "이 노트로 이어서" 도구가
따로 답한다. 둘을 같은 화면에 **같은 모양으로** 두면 독자가 구별할 방법이 없다.

## 3. 29 persona — 이월 사유를 확정한다

984에서 "노트 성격이라는 별도 개념이 필요하다"며 미뤘다. 이번에 다시 보고
**만들지 않기로 확정**한다. 980의 persona 는 **도구 12종을 서로 구분하기 위한**
장치다(색·성격 라벨·연출). 노트는 12종이 아니라 한 종류이고, 노트끼리 구분해야
하는 축은 성격이 아니라 **단지·시점**이다. 노트에 성격을 붙이면 화면은 화려해지고
읽는 사람이 얻는 것은 없다. 26의 종이 면이 노트가 필요로 한 개성의 전부다.

## 4. 바깥 피드백 — 후기 페이지 제안에 대한 답

제안: "고객 후기 페이지를 만들라."

**지금 인용할 사람이 아무도 없다.** 실측: 가입 14명 · 외부 공개 노트 0건 ·
`complex_reviews` 0행 · `expert_reviews` 0행. 없는 후기를 지어내는 것은 이
저장소가 금지한 일이고, 983에서 "운영진 예시" 라벨을 붙여 과장을 걷어낸 것과도
정면으로 어긋난다. 그래서 후기 페이지 대신 **두 가지**를 했다.

### 4-1. 신뢰 근거 — 가진 것을 그대로 보여 준다

`/data-sources` 는 출처와 갱신 주기를 **글로** 적어 두었지만 실수치가 하나도
없었다(정적 페이지, DB 조회 0). 주기를 적어 두면 사람은 그 주기가 지켜지고 있다고
읽는다 — **982에서 단지 대장 적재가 13일간 실패하는 동안 화면에는 아무 표시도
없었다.**

이제 페이지가 직접 센 값을 보여 준다:
- 실거래 신고분(취소 제외) · 실거래 있는 단지 · 실거래 있는 시군구
- 원천별 **마지막으로 성공한 적재 시각** ("3시간 전" / "2일 전 · 밀림")

원칙:
- **성공한 적재만 센다.** 실패한 시도를 "갱신됨"으로 보이게 하는 게 제일 나쁜 거짓말이다.
- **48시간이 넘으면 밀렸다고 적는다.** 며칠씩 밀린 것을 "최근"으로 뭉개지 않는다.
- **못 읽으면 그 줄을 뺀다.** 추정치로 채우지 않는다. 다 못 읽으면 그렇다고 적는다
  (로컬 실측: 서비스 클라이언트가 없을 때 "지금은 수치를 불러오지 못했어요"가 뜬다).
- 30일이 넘으면 "며칠 전" 대신 날짜를 적는다 — 그쯤 되면 "며칠 전"이 위로가 안 된다.

후기가 한 건도 없는 서비스가 "왜 믿어야 하나"에 답하는 방법은 지어낸 추천사가
아니라 이것이다.

### 4-2. 후기 **수집 장치**를 먼저 둔다

엄지(도움됨/부족함)만 받으면 숫자가 쌓이지 후기가 쌓이지 않는다 — 인용할 수
있는 건 문장이다. 피드백 자리에 **한 줄**을 받는 칸을 붙였다(선택).

- **인용 동의를 따로 받는다.** "이 문장을 내집나우 소개에 이름 없이 인용해도
  좋아요" 체크. 동의 없이 쓴 문장을 나중에 소개에 올리는 일이 없게, 동의 여부를
  문장과 같이 저장한다.
- **새 테이블을 만들지 않는다.** 기존 이벤트(`platform_activity_events`)의
  context 로 실어 보낸다. 후기가 실제로 쌓이기 전에 스키마부터 만드는 것은 이
  세션에서 계속 피해 온 순서다(재방문 알림·동행 작성과 같은 이유).
- **서버에서 다시 자른다.** 300자 클램프는 클라이언트에도 있지만 그건 편의일
  뿐이다. 인용 동의는 boolean 만 받는다(`"true"` 같은 문자열을 참으로 읽지 않는다).
- **아직 어디에도 공개되지 않는다.** 나중에 인용하려면 `quotable === true` 인
  것만 고르고 그때 금칙어 검사를 통과시켜야 한다 — 지금 안 거치는 이유는 공개
  표면이 없어서지 필요 없어서가 아니다(라우트 주석에 적어 뒀다).

**후기 페이지를 여는 조건**: 인용 동의된 문장이 5건 이상 쌓였을 때. 그전에는
열지 않는다.

### 4-3. 첫 노트 우선 — 이미 한 일

이 항목은 984·985가 그대로 답이다: 3단계(문서 높이 3,854 → 1,322px) · "여기까지
저장" · 단지 이어받기 · 한 손 모드 · 오프라인 사진 · 현장 브리핑. 별도로 더
만들 것을 찾지 않았다.

## 5. 검사

```
npm run build              전체 게이트 통과 · 단위 테스트 552건
check:contrast-tokens      라이트·다크 51조합 전부 통과 (종이 면 포함)
npm run check:mobile       ✓ 8개 기본 경로 + /data-sources·/methodology·/about
npm run check:void:mobile  ✓ 8개 경로 + /data-sources
번들 예산                   6/6 통과
```

`/data-sources` 는 실수치를 읽어야 해서 `force-static` → `force-dynamic` 으로
바꿨다(숫자는 6시간 캐시라 매 요청마다 DB 를 두드리지 않는다). prerender 페이지가
290 → 289로 하나 줄어든 건 그 때문이다.

종이 면은 노트 상세가 클라이언트 렌더라 로컬(서비스 클라이언트 없음)에서는
데이터가 안 올라온다. 그래서 CSS 를 실제 페이지에 주입해 라이트·다크 양쪽
스크린샷으로 확인했다 — 글자가 괘선에 앉는지, 다크에서 대비가 유지되는지.
