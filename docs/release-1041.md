# 1041 — 비밀번호 변경 알림 문구를 실제 발송 여부에 맞춤

소유자 질문(2026-10-06) "회원가입 시 이메일보내기가 실제로 작동하고 있어?"를 확인하다 찾은 1040 의 잘못 하나를 고친다.
1040 위에 누적. DB·가격·상품 변경 없음.

## 확인한 것 (운영 DB 기록 · Vercel 설정 이름만 읽음 — 실제 가입·재설정 요청은 일으키지 않음)

| 메일 | 보내는 곳 | 상태 |
|---|---|---|
| 가입 인증 메일 | Supabase Auth | 나간다 — 가입 15명 중 발송 9 · 인증 완료 5 · 미완료 4. 8월 2건은 1~4분 안에 인증. 최근 1건(9-12 · 네이버 주소)은 미인증(스팸함인지 안 누른 것인지 기록으로는 모름) |
| 비밀번호 찾기 메일 | Supabase Auth(대신 가는 길) | 길은 있음 — 요청 0건이라 실측 없음 |
| 환영 · 비밀번호 변경 알림 · 문의 답변 · 결제 영수증·갱신 사전 통지 · 주간 요약 · 관심 단지 새 거래 · 탈퇴 접수 · 관리자 로그인 알림 | 사이트(Resend) | **전부 미발송** — 운영에 `RESEND_API_KEY` 가 없다(`sendEmail` 은 조용히 건너뜀). 환영 메일 받은 회원 0 · 자체 재설정 토큰 0행 |

- Vercel 의 `SMTP_HOST` 등 6개(6월 등록)는 읽는 코드가 없다 — 쓰이지 않는 설정.
- Supabase 가 자체 SMTP 를 쓰는지 기본 발송기(시간당 제한 · 스팸함 가기 쉬움)를 쓰는지는 대시보드에서만 보인다(Authentication → Emails → SMTP Settings).

## 고친 것

1040 은 비밀번호를 바꾸면 화면에 늘 "알림 메일 발송"이라고 적었다. 운영에서는 한 통도 나가지 않는다 — 없는 일을 적은 것.

| 자리 | 1040 | 1041 |
|---|---|---|
| 재설정 완료 | 3초 뒤 로그인 화면 · 변경 알림 메일 발송 | 3초 뒤 로그인 화면 (서버가 실제로 보냈으면 "· 변경 알림 메일 발송") |
| 재설정 폼 아래 | 변경 즉시 적용 · 알림 메일 발송 | 변경 즉시 적용 |
| 설정 › 비밀번호 변경 완료 | 변경 완료 · 알림 메일 발송 | 변경 완료 · 즉시 적용 (보냈으면 "변경 완료 · 알림 메일 발송") |

- `sendPasswordChangedNotice` 가 **보냈는가**를 돌려준다(미설정·실패 = false) → 두 API(`/api/auth/reset-password` · `/api/me/password`)가 `noticeSent` 로 싣는다 → 화면은 `passwordChangedLine()`(lib/auth/auth-ux.ts) 한 곳으로만 적는다.
- 발송 키를 넣으면 코드 변경 없이 문구가 따라온다.

## 손대지 않은 것 (소유자 결정)

- 요금제 화면의 "즉시 적용 · 영수증 메일"(심사 동결 화면) · 문의 폼의 "입력한 이메일로 보내 드려요" — 지금은 사이트가 메일을 못 보낸다. 문구가 아니라 발송을 살려야 맞다(아래).
- 발송 살리기: ① Vercel 에 `RESEND_API_KEY` + `EMAIL_FROM`(Resend 에서 인증한 도메인) — 코드 변경 없음. ② 또는 이미 들어 있는 `SMTP_*` 6개로 보내도록 코드를 바꾼다(의존성 1개 추가 · 16곳이 한꺼번에 켜진다) — 지시가 있으면 진행.

## 검증
- `npm run build` 전체 통과 · 단위 +5(`auth-1041`).
- 전후 캡처 3장면(폰). 재설정·비밀번호 변경 API 응답은 브라우저 안에서 가짜로 돌렸다(운영 서버에 요청 없음).
