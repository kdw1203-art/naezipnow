# 1066 — 검색이 못 읽던 네 가지 (진짜 404 · h1 하나 · 이미지 설명 · 홈 제목)

소유자 지시 2026-10-13: "다시 검토해줘" → 검토 결과 네 항목 제시 → 선택 **"없는 주소 404 까지 전부"**.
1060 에서 적어 두고 못 고친 항목들이다. 이번에는 **원인을 실측으로 확정**한 뒤 고쳤다.
화면 디자인은 바꾸지 않았다(1065 가 반려된 뒤라 보이는 것은 손대지 않는다). DB 변경 없음 · 가격·심사 문구 변경 없음.

## 1. 없는 주소가 HTTP 200 으로 나갔다 (소프트 404)

운영 실측 2026-10-13 — 12개 상세 경로 중 **11개가 200**, `/tx/...` 만 404.

| 경로 | 전 | 원인 |
|---|---|---|
| /complex/[id] /notes/[id] /town/news/[id] /region/[id] /region/[id]/report /reports/[ym] /redevelopment/[id] /rent/[region] /imjang/[slug] /digest/[week] /notes/best/[ym] | 200 | 그 경로를 덮는 `loading.tsx` 가 있다 |
| /tx/[region]/[band] | 404 | 덮는 `loading.tsx` 가 없다 |

상세 페이지들은 **이미 `notFound()` 를 부르고 있었다.** 그런데도 200 이었다.
`app/complex/[id]/page.tsx` 에 2026-08-10 실측 메모가 남아 있다 — "loading.tsx 스트리밍 때문에 200 이
먼저 커밋된다 … 진짜 404 를 원하면 loading 경계 위에서 존재 확인이 필요하다(구조 변경 — 워크오더)".

### 어디서 404 가 살아남는지 탐침 네 벌로 실측

임시 경로 `app/zz-probe/{a,b,c,d}/[id]` 를 만들어 로컬 `next start` 로 상태 코드를 쟀다(측정 뒤 삭제).

| 탐침 | 구성 | 결과 |
|---|---|---|
| a | 자기 세그먼트 `loading.tsx` + **`layout.tsx`** 에서 notFound() | **404** |
| b | **조상** 세그먼트 `loading.tsx` + 자기 `layout.tsx` 에서 notFound() | 200 |
| c | 경계 없음 + `page.tsx` 에서 notFound() | **404** |
| d | 자기 세그먼트 `loading.tsx` + `page.tsx` 에서 notFound() | 200 ← 종전 상태 |

Next 는 한 세그먼트를 `layout > Suspense(loading) > page` 로 감는다. `page` 의 `notFound()` 는
그 Suspense 안에서 잡혀 상태가 200 으로 굳고, **`layout` 은 경계 밖**이라 404 가 그대로 나간다.
조상 세그먼트의 경계는 자식 레이아웃까지 감싸므로 자식 쪽 `layout` 으로도 뚫리지 않는다(b).

### 그래서 한 일

- **존재 확인을 `layout.tsx` 로** (자기 세그먼트에 스켈레톤이 남아 있는 네 곳):
  `app/complex/[id]` · `app/notes/[id]` · `app/region/[id]` · `app/rent/[region]`.
  **스켈레톤은 지우지 않았다** — 로딩 중 빈 화면을 만들지 않으려고 이 방식을 골랐다.
- **조상 스켈레톤을 라우트 그룹 안으로** (여섯 곳): `app/<목록>/page.tsx` + `loading.tsx` →
  `app/<목록>/(index)/`. 라우트 그룹은 주소를 바꾸지 않으므로 `/notes` `/town/news` `/reports`
  `/redevelopment` `/imjang` `/digest` 는 그대로이고, 목록 화면의 스켈레톤도 그대로다.
  그 아래 상세 경로에서는 경계가 사라져 `page.tsx` 의 `notFound()` 가 404 로 나간다(탐침 c).
- 판단 기준은 본문과 **같은 줄**을 쓴다. 지역은 "부동산원 통계가 없어도 카탈로그에 있으면 있는
  지역"(2026-07 신설 구) 그대로, 노트는 **없는 노트 한 가지**만 거르고 비공개·구매 열람 판단은
  보는 사람에 따라 갈리므로 본문에 남겼다. 조회 **실패**는 404 가 아니라 던진다(5xx) — "지금은
  못 준다"를 "없다"로 바꾸지 않는다.
- 노트는 같은 요청에서 조회가 두 번 나가지 않게 로더를 공용 모듈로 옮겼다
  (`app/notes/[id]/load-note.ts` — React `cache()` 는 함수 정체성으로 묶이므로 한 모듈이어야 한다).
  단지는 ISR(revalidate 1주)이라 캐시 미스에만 존재 확인 한 번이 늘고, 꼴이 어긋난 id 는
  `parseComplexId` 가 질의 없이 걸러 404 가 된다.

### 남은 한 자리

`/region/[id]/report` 는 "지역이 없다"면 404 가 되지만(위 레이아웃), "지역은 있는데 그 달 리포트가
없다"는 조상 경계(`app/region/[id]/loading.tsx`) 안이라 여전히 200 + noindex 다. 사이트맵에 올라가지
않는 자리이고 색인 유입이 없어 이번에는 두었다.

## 2. 한 주소에 h1 이 두 개

운영 실측: `/town/news` `/supply` `/auctions` `/redevelopment` `/redevelopment/seoul`
`/redevelopment/seoul/<구>` `/imjang` `/imjang/<지역>` 가 h1 2개.

범인은 **로딩 스켈레톤**이었다. `loading.tsx` 열 곳이 `TownHero` · `NewsHead` · `PageShell title` 로
각자 h1 을 내고, 스트리밍 셸이라 실제 화면의 h1 과 **같은 문서에 함께** 나간다.

고친 방식: 부품 셋에 머리 단계를 받는 prop 을 더하고(`PageShell titleAs` · `TownHero as` ·
`NewsHead as`, 기본값은 h1 그대로) **스켈레톤만 h2** 로 받게 했다. 글자 모양은 램프 클래스(`t-title`)가
정하므로 화면은 한 픽셀도 바뀌지 않는다.

## 3. 썸네일 설명(alt)이 비어 있었다

운영 실측: 뉴스 목록 `<img>` 40장 중 40장, 노트 목록 142장 중 38장, 홈 3장 중 3장이 `alt=""`.
이미지 검색에 한 장도 잡히지 않는다.

색인되는 목록 썸네일 여덟 자리를 채웠다 — 기사는 **제목 그대로**(사진인지 도표인지 단정하지 않는다),
노트 커버는 기존 문장 꼴을 따라 `"<제목> 노트 커버"`(206행 선례). 장식 그림(`Illust`)과 편집기·
라이트박스·고르기 화면은 그대로 비워 뒀다 — 읽기 보조기기에 잡음을 늘릴 자리다.

## 4. 홈 title 에 검색되는 말이 없었다

전: `내집나우 — 시세는 누구나 봅니다, 현장은 가 본 사람만 압니다`
후: `아파트 실거래가 조회·임장노트 — 내집나우 | 시세는 누구나 봅니다, 현장은 가 본 사람만 압니다`

검색 결과는 앞 30자쯤에서 잘리므로 순서가 전부다. 브랜드 문장(전략 정본 §6)은 지우지 않고 뒤로
옮겼다 — 탭·방문 기록에는 그대로 보이고, 공유 카드(`openGraph.title`)는 **바꾸지 않았다**.
