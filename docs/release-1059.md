# 1059 — 6가지: 임장노트·매물 "저장"을 코드만으로 — DB 제약을 바꾸지 않고 프로필 설정에 저장

소유자 지시(2026-10-12): "아래 사항도 코드로 할 수 있도록 해줘" — 1056~1058 에서 부탁한 Supabase SQL(bookmarks CHECK 교체) 없이 되게.

1058(트리 54ba034d — 소유자 적용 전이면 이 묶음이 1058 을 포함한다) 위에 누적. 가격·상품·요금제·결제 화면 변경 없음. **DB 변경 없음**(스키마·제약·마이그레이션 전부 그대로).

근거: 운영 DB 의 `bookmarks_target_type_check` 는 post·report·expert·meeting·market·complex 만 허용해 매물 저장은 거절되고 노트 저장은 만들 수 없었다. 제약 교체는 삭제 문이 필요해
이 저장소 규약(가산만)과 이 세션의 도구 정책이 막는다. 바꾸지 않아도 되는 자리 — **모든 계정에 이미 있는 프로필 행의 설정 jsonb**(profiles.settings · auth 트리거가 만든다 · 닉네임 효과도 같은 열) — 에
`saved = { note: [{id, at, label}], listing: [...] }` 로 담는다(종류당 300개 · 동시 갱신은 updated_at 조건 + 재시도).

1. `lib/bookmarks/settings-store.ts` — 프로필 설정 jsonb 저장소(넣기·빼기·목록·여부·한도·"이 노트를 저장한 사람 수" 포함 질의). 순수 규칙(모양 검사·중복·상한)은 시험으로 잠금.
2. `lib/bookmarks/store.ts` — 바깥 API 는 그대로, 종류가 note·listing 이면 설정 jsonb 로, 나머지는 표로. 플랜 한도(countBookmarks)는 표 + 설정 합산. 매물 "저장"(ListingSaveButton)이 이제 실제로 저장된다.
3. `/api/bookmarks` — `type=note` 허용 · `?type=&id=` 로 한 대상의 저장 여부 · 해제 실패 503 "저장 해제 실패 · 잠시 후 다시".
4. 노트 상세 "저장 / 저장됨" 단추(남의 공개 노트 · 로그인 힌트 없으면 서버에 묻지 않고 가입·로그인 창 · 폰 40px · aria-pressed).
5. 마이 홈 "저장한 노트"가 실제 목록(최신 10 · 비공개로 바뀐 노트 제외) · 관심 › **저장** 탭에 "저장한 노트" 묶음(30건 · 비공개로 바뀐 N건 숨김 표시).
6. 크리에이터 "저장" 타일 — "저장 집계 없음" → 내 공개 노트(20편)를 저장한 사람 수(못 세면 "—").

## 남긴 것

- 회원이 수만 명이 되면 "저장한 사람 수" 포함 질의에 색인(또는 표)이 필요하다 — 그때 표로 옮긴다(저장 모양은 그대로 옮길 수 있다).
