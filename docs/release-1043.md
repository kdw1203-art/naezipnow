## 1. 뉴스룸 머리 — 다른 동네 카테고리와 같은 부품·순서

| | 예전 | 지금 |
|---|---|---|
| 머리 | 뉴스룸만의 머리: 제목 "부동산 뉴스" · 날짜 줄 · 버튼 둘(동네이야기 · 주간 다이제스트) · 숫자 줄(오늘 n건 · 최근 n건 · 같은 사건 묶어 n건) | 청약 센터·공매·입주·정비와 같은 `TownHero`: 아이콘 칩 + "뉴스룸" + 한 줄 + 버튼 하나(주간 다이제스트) |
| 순서 | 머리 → 주제 칩 → 카테고리 줄 | 머리 → 카테고리 줄 → 주제 칩(본문 첫 줄) |
| 숫자 | 머리의 숫자 줄 | 없음 — 목록 위 "40 / 254건 · 같은 사건은 한 건으로 묶음"이 같은 사실을 말한다 |

- 동네 홈의 카테고리 줄에서 뉴스룸 칸에만 붙던 "오늘 기사 n건"도 내렸다(여섯 칸이 같은 모양).
- 하위 화면의 카테고리 줄이 본문보다 오른쪽이 20px(폰 14px) 짧던 것 수정(`w-full` + 음수 여백 → 폭 auto).
- 뉴스 목록(행)은 손대지 않았다.

## 2. 동네이야기 = 이웃 글만

- `/town` 피드는 이웃 글만 읽는다(`lib/town/feed.ts` — 공개 노트 조회 삭제). 공개 임장노트는 `/notes`(임장노트 › 공개 노트)가 맡는다.
- 유형 칸(전체 · 임장노트 · 이야기) 삭제 · 머리의 "임장노트 쓰기" 삭제 · 한 줄 "이웃 글 · 동네 단위" · 숫자 줄은 글이 있을 때만.
- 지금 운영에는 이웃 글이 0건이다 → 화면은 "이웃 글 없음 · 첫 이야기 쓰기"로 열린다(지어내지 않는다). 오늘의 뉴스 줄·동네 홈 바로가기·동네 홈 전체는 그대로.
- 예전 주소 `?kind=note` 는 같은 목록으로 열리고 주소에서 kind 가 지워진다.

## 3. 임장노트 독자 평가(별점) + 댓글

- 공개 임장노트 상세의 댓글 카드 위에 **독자 평가**: 평균 · 별 · 인원 + 내 평가(별 다섯 개 · 칸마다 40px). 누르면 바로 저장, 다시 누르면 바뀐다.
- 규칙: 로그인한 사람만 · 공개 노트에만 · **내 노트는 평가 불가** · 한 사람 한 노트 한 번. 0명은 "평가 없음"(0점이라고 적지 않는다).
- 누가 몇 점을 줬는지는 서버 밖으로 나가지 않는다(평균 · 인원 · 내 점수뿐). 첫 평가 때 작성자에게 인앱 알림(점수 없이).
- 노트 머리에 "독자 평가 4.3 · 12명" · "댓글 3" 칩(있을 때만 · 누르면 아래 칸으로). 공개 노트 목록 카드의 바닥줄에도 **있을 때만** 덧붙는다(0 이면 카드는 예전 그대로).
- 댓글은 이미 있던 기능(1단계 답글 · 신고 · 삭제)이다 — 평가와 한 카드로 묶었고 목록에 댓글 수가 보이게 했다.
- DB: `note_ratings`(적용 완료 · 미러 `supabase/migrations/20261006150529_1043_note_ratings.sql` · RLS 켜고 정책 없음 = 서버 전용).
- 파일: `lib/inspection/note-rating-math.ts`(순수) · `note-ratings.ts` · `app/api/inspection/notes/[id]/rating/route.ts` · `app/notes/[id]/NoteRating.tsx` · `page.tsx` · `lib/notes/feed-note.ts`.

## 4. 지오코딩

| 문제 | 원인(확인한 것) | 한 일 |
|---|---|---|
| 거래 많은 신축이 지도에 없다 — 지제역더샵센트럴시티(매매 297건) · 루원시티SK리더스뷰(253) · 캐슬앤파밀리에시티(236) … | 실거래 지번이 "가-" · "BL-" 같은 블록 자리라 주소가 아니다 | 같은 단지의 **전월세 신고에 있는 도로명 주소**(raw.roadnm "지제동삭1로 41")와 다른 거래 행의 진짜 지번을 두 번째 후보로 쓴다. 대상 312곳 중 도로명 134 · 진짜 지번 210 · 둘 다 없음 20 |
| 다른 도시에 찍힌 좌표 | 단지명만으로 물은 후보가 지명으로 읽혔다 — 인천 계양구 "동서" → 312km 밖 등 6건, 동 한가운데 2건 | 단지명 후보 삭제 · 돌아온 주소의 시·도가 기대와 다르면 버린다 · 그 8건은 좌표를 비우고 다시 묻게 했다(DB) |
| 분양 단지 348건 못 찾음 | 공고 주소의 꼬리("번지 일원" · "외 157필지" · 괄호) · 한 번 못 찾으면 영영 재시도 없음 | 꼬리를 떼고 묻는다(`cleanLotAddress`) · 7일 뒤 재시도 · 하루 25 → 60건 |
| 재시도가 옛 빈 답을 받는다 | 지오코더 호출이 7일 데이터 캐시를 탔다 | 백필 호출은 캐시 없이 |
| 관리 화면 진행률이 늘 100% · 남음 0 | 분자(좌표 행 전체)와 분모(매매 단지 수)의 모집단이 달랐다 · 신선도 화면 카드는 없는 열을 세어 한 번도 안 그려졌다 | `public.geocode_coverage()` 한 곳에서 같은 모집단으로 센다(좌표 있음 + 못 찾음 + 미시도 = 전체 · 분양 단지는 따로) |

- DB(적용 완료 · 미러 `20261006152844_1043_geocode_coverage_and_requeue.sql`): `geocode_coverage()` · `complexes_needing_geocode_v2(p_limit, p_retry_before)`(규칙이 바뀌기 전에 못 찾은 행을 7일 기다리지 않고 한 번 다시 묻는다) · 잘못 찍힌 8건 되돌리기.
- **확인하지 못한 것**: 네이버 지오코더를 여기서 부를 수 없어(키는 운영에만 있다) 새 후보의 실제 성공률은 재지 못했다. 규칙(후보·검증·주소 정리)은 운영의 실제 실패 주소로 단위 테스트했다. 적용 뒤 첫 실행(매일 10:20 KST · 또는 관리 › 데이터의 실행 단추)에서 로그에 `성공=n(거래 단서 m) 못찾음=k`가 남는다.
- 손대지 않은 것: region_name 에 도 이름이 없어 강원 고성군과 경남 고성군이 한 키로 합쳐진다(실거래 적재 키를 바꿔야 하는 일 — 별도 판단).

## 5. 성능

**먼저 밝힐 것 — 표의 빨간 칸 대부분은 사람이 아니었다.** 최근 7일 `web_vitals` 450행 중 126행이 운영 화면을 캡처·점검하던 자동 브라우저(이 작업의 예전 캡처 스크립트)의 표본이었다. 그 세션은 캐시가 비어 있고 글꼴이 매번 늦게 바뀐다.

| 표의 칸 | 그 표본 | 같은 기간 사람 표본 |
|---|---|---|
| /town LCP 5.9초 | 로봇 1건 | 0.17초(1건) |
| /search CLS 0.816 | 로봇 2건 | 0(1건) |
| /my CLS 0.246 | 로봇 4건 | 없음 |
| /subscription/checkout LCP 6.4초 | 로봇 1건 | 없음 |

- 막은 것: 점검 스크립트가 `localStorage.nz_probe = "1"` 을 심고, 지표 보고가 그 표식이 있으면 보내지 않는다(`lib/client/probe.ts`). 관리 › 성능은 표식 이전(~10-07)의 로봇 표본(고정 UA 3종)을 빼고 세고, 몇 건을 뺐는지 적는다.

사람 표본에서 실제로 느린 것과 한 일:

| 실측(사람) | 한 일 |
|---|---|
| 단지 화면 TTFB 1.0~1.2초(안드로이드 · 처음 열리는 단지) | 화면 길의 외부 지오코더 호출 삭제(위 4) · 표식 조회와 해제 행 조회를 함께 띄움 |
| 뉴스 상세 TTFB 0.87~1.13초 | 글·숨김·관련글 조회를 함께 띄움 · posts/board_posts 두 조회 동시 · 연관 단지·태그 링크 동시 |
| 단지 화면 타입 탭 INP 320~328ms(안드로이드) | 누른 단추 표시가 먼저, 그래프는 뒤따라(`useDeferredValue`) |
| 재방문의 모든 페이지 이동 | 서비스워커 내비게이션 프리로드 — 워커가 깨는 동안 요청이 먼저 나간다 |
| 검색 화면 — 결과가 오면 푸터가 밀림(데스크톱에서 푸터 윗부분이 첫 화면에 걸려 있었다 — 실측 741px / 화면 768px) | 결과 영역 최소 높이 70vh → 100dvh(실측 972px — 첫 화면 밖) |

- 재현되지 않아 넣지 않은 것: 쿠키 배너 여백이 푸터를 끌어올린다는 가설(실측 — 배너 전후 푸터 위치 같음).
- 남은 것(결정 필요): 윈도우·안드로이드의 **첫 방문**에서 웹폰트(Pretendard)가 늦게 바뀌며 머리 메뉴가 12~30px 움직인다(캐시가 생긴 재방문은 이동 없음 — 실측). 없애려면 첫 방문을 시스템 글꼴로 그려야 한다 — 글꼴이 달라 보이는 결정이라 묻고 진행한다.
- 손대지 않은 것: 결제 화면(심사 동결) — 주문 요약이 토스 결제 위젯이 뜬 뒤에야 그려지는 구조라 LCP 가 위젯 로딩에 묶여 있다(사람 표본 없음).
- 표본이 매우 적다(사람 324행/7일 · 표본 추출 20%). 적용 뒤 1~2주 숫자로 다시 본다.
