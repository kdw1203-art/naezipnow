## 1. 상단 — 헤더 가운데 빈 칸과 그 아래 빈 띠

**측정**: 393px 폭에서 헤더 내용은 `로고 93px` + `오른쪽 아이콘 묶음 120px` 이고,
그 사이 **49px 이 아무것도 없이** 떠 있었다. 검색은 19px 짜리 돋보기 아이콘 하나로만
들어갈 수 있었다. 헤더 아래에서 첫 문장("어느 단지가 궁금하세요?")까지는 다시 **40px**
가 비어 있었다.

| 바뀐 것 | 파일 |
|---|---|
| 빈 칸에 **검색 필드**를 넣었다 — 데스크탑 HeaderSearch 와 같은 재질(`--glass-bg`)·같은 자리. 오른쪽의 돋보기 아이콘은 이것으로 대체해 뺐다(같은 헤더에 검색 진입점이 둘일 이유가 없다). 좁은 폭을 벌려 주려고 아이콘 묶음 간격 12→8px, 셸 좌우 16→14px. | `app/components/Header.tsx` |
| 히어로 위 여백 `pt-5`(20px) → `pt-1.5`(6px) | `app/page.tsx` |

입력이 아니라 **링크**로 둔 이유: sticky 헤더 안에서 키보드를 올리면 헤더가 뷰포트와
함께 튀고, `/search` 가 최근 검색·자동완성을 이미 갖고 있다.

## 2. 하단 — 카드가 버튼을 덮고, 푸터 마지막 줄이 FAB 에 가림

**측정(홈, 임시저장 노트가 있을 때)**: primary CTA "임장노트 쓰기" 가 540.6~587.1,
"작성 중인 노트 이어서 쓰기" 팝업이 584.8~651 — **겹쳐 있었다.** 캡처의 하단 표시가
정확히 이 자리다. 페이지 끝에서는 푸터 마지막 줄의 오른쪽 글자가 "맨 위로" FAB
(44px, right 14px) 밑에 깔렸고, 그 아래로 **60px 짜리 흰 띠**가 남았다.

| 바뀐 것 | 근거 |
|---|---|
| 팝업이 떠 있는 동안 본문 아래를 그 높이만큼 비운다(`body.nz-has-resume`, 단지 액션 바 `.nz-has-actionbar` 와 같은 방식). "맨 위로" 도 같이 올린다 — 안 올리면 이번엔 FAB 가 카드를 덮는다. | CTA 526.6~573.1 · 팝업 584.8~651 → **11.7px 여유** |
| 푸터 마지막 문단에만 오른쪽 여백 `pe-[68px]`(md+ 는 원래대로) — FAB 는 fixed 라 스크롤로 피할 수 없다. | 마지막 줄이 FAB 를 피해 3줄로 접힌다 |
| 푸터 아래 여백 `pb-28`(112px) → `pb-[76px]` = 탭바 오프셋 68 + 8 | 덮이지도, 남지도 않는 최소값 |

## 3. 동네이야기 9칸 — 머리 모양 통일

`TownPageHead` 의 주석은 "개편 전에는 다섯 가지가 섞여 있었다… 한 모양으로 통일한다"
라고 적혀 있는데, **9칸 중 2칸이 그 통일에서 빠져 있었다.**

| 페이지 | 970까지 | 972 |
|---|---|---|
| /redevelopment | `PageShell title` 을 써서 **h1 이 카테고리 줄 위**에 그려짐 → 제목 위치 **102px** · 브레드크럼도 혼자 "홈 › …" | 공통 머리로 · "동네이야기 › …" |
| /town/experts | 카테고리 줄 바로 아래 **네이비 히어로**(h1 이 그 안) → 제목 위치 **258px** | 공통 머리 + 네이비 카드는 소개 블록으로 강등(내용은 그대로) |
| 나머지 7칸 | 214px | 214px |

**결과: 9칸 전부 h1 이 214px · 19px · `<h1>`** (Pixel 5 실측, 아래 검증표).

곁들여 정리한 것:

- 본문 폭이 갈려 있었다 — `wide`(1400px)가 /qna·/apply·/supply·/auctions 넷에만 있었다. 부모(/town)가 `wide` 이므로 9칸 모두 `wide` 로 맞췄다(모바일 영향 없음, 데스크탑 폭 통일).
- /town/experts 에서 "전문가로 참여" 가 머리와 히어로에 **두 번** 있었다 → 머리의 action 하나만 남겼다.
- /redevelopment 소개 문단이 새 부제와 같은 말을 반복해 첫 문장을 덜어냈다.

### 검증 중에 만난 것 (코드 문제 아님)

로컬에서 `next build` 를 반복하면 `.next` 안에 **이전 빌드의 HTML 이 남아** 없는 자산
해시(`css/f1de9abc…`)를 가리키는 페이지가 섞였다. 그 상태로 스크린샷을 찍으면 CSS 가
통째로 빠진 화면이 나와 "레이아웃이 깨졌다"고 오독하게 된다. `rm -rf .next` 후 재빌드로
확인했다 — Vercel 은 매번 새로 빌드하므로 운영에는 없는 현상이다. 이 문단은 다음에
같은 착시를 겪지 않으려고 남긴다.
