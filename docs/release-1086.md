## A. 가입·활동 전환

## B. 서울 3D 동네 지도 — `/map/3d?region=서울 강남구&dong=개포동`

| 층 | 원천 | 비고 |
|---|---|---|
| 건물 · 높이 | OpenFreeMap 벡터 타일(OpenStreetMap · OpenMapTiles 스키마 `render_height`) | 키 없음 · 출처 표기(© OpenFreeMap © OpenMapTiles © OpenStreetMap) · 높이·층수 태그가 없는 건물은 낮게 |
| 단지 이름 · 색 | 우리 DB(지도와 같은 원천 map_price_point_source · 동 페이지와 같은 search_complexes_filtered · map_complex_attrs) | 평당 평균 매매가 5단계(4천만 미만 · 4천만~6천만 · 6천만~8천만 · 8천만~1.2억 · 1.2억 이상 — 서울 분포 기준) · 집계 기간 표기 |
| 단지 건물 칠하기 | 단지 좌표 반경(세대수로 70~260m) 안 15m 이상 건물 · 겹치면 가장 가까운 단지 하나 | **위치 기준 추정**이라고 화면에 적는다 |
| 역 | 타일의 철도·지하철 POI | 이름 옆 숫자 = 반경 600m 안 이 동 단지 수 |
| 학교 | 타일의 school POI | 한국어 이름표 |

- 화면: 동 단위 · 3D/위에서 전환 · 단지 목록·검색(폰은 "목록" 접기) · 단지를 누르면 카드(평당 평균 · 매매 신고 · 세대수 · 준공 · "단지 화면" · "동 실거래") · 다크 모드는 화면 토큰을 그대로 받는다.
- API `/api/map/3d`: CDN 하루(s-maxage 86400 · SWR) · 서울만(그 밖 404) · 조회 실패 503(캐시 없음). 운영 데이터로 개포동 97단지(이 동 42 · 주변 1.6km).
- 진입: 동 페이지 "{동} 3D로 보기"(서울만) · 단지 화면 칩 "3D 동네 ›"(그 단지를 고른 채로 연다). 3D 화면은 색인하지 않는다(같은 내용의 동 페이지가 색인 대상).
- 지도 엔진 MapLibre GL JS 5.24.0(정확한 판 고정) — 이 화면에서만 받는다(다른 화면 첫 로드 무관). WebGL 이 없는 기기는 안내 문구.
- 테스트 중 찾은 계산 오류: 건물 중심 계산이 서울 좌표를 그대로 곱해 반올림 오차로 최대 10m 가까이 어긋났다 → 첫 꼭짓점 기준으로 옮겨 계산(오차 0.05m 미만).

## 번들 예산(올리지 않음)

첫 빌드에서 노트 쓰기 화면이 474KB(예산 470) · 마이 설정이 496KB(미등재 상한 495)로 막혔다. 1085 트리를 같은 조건으로 따로 빌드해 청크끼리 비교한 결과:

- 모든 화면 +1.4KB = webpack 런타임에 **CSS 지연 로더**가 붙음 — 3D 지도 엔진 CSS 를 지연 청크에서 import 한 탓. → 3D 화면(page.tsx)의 정적 CSS 로 옮김(런타임 원상).
- 노트 쓰기 +2.8KB = 가입 재개 코드 · 재개 표식 모듈 · 계측 모듈. → 재개 표식 모듈을 URL API 로 줄이고 계측은 그때만 받기 · "됐다" 장면(MomentProvider)의 문맥·훅을 작은 모듈(moment-context)로 나눠 화면 번들이 장면 그리기 코드(약 2.3KB)를 받지 않게(노트 쓰기 · 가입 · 로그인 · 동네 글쓰기 · 모임 · 여정). 가입 창(SoftSignupProvider)도 같은 방식 — 부르는 화면 21곳이 문맥 모듈(soft-signup-context)만 받아 창 그리기·실험 등록부(약 5KB)가 화면 번들에서 빠진다(루트 레이아웃엔 그대로).
- 마이 설정: 뉴스레터 계측 모듈을 켜는 순간에만 받기(미등재 상한 495KB 에 0.4KB 남아 있었다).
- 결과(로컬 빌드 · 1085 같은 조건 대비): 노트 쓰기 469.9 → 464KB · 단지 478.3 → 474KB · 마이 설정 494.3 → 493.8KB · 홈 486KB 그대로.
