## 기능 1 — 죽은 링크 6,003개

로컬에서 주요 화면 8곳의 내부 링크 806개를 전부 열어 보니 404 가 11개 — 전부 동 화면(상계동)의 "나머지" 단지 목록이었다.
원인은 원천의 차이다. 단지 목록 · 검색이 읽는 `search_complex_mv`(단지 40,317곳)에는 **전월세만 있는 단지가 6,003곳** 들어 있는데,
단지 화면은 매매 실거래가 한 건은 있어야 존재한다(`complex/[id]/layout` → `getComplexBaseById`: trade · apartment). 그 6,003곳에 링크를 걸던 곳:

| 어디 | 원천 | 고친 것 |
|---|---|---|
| 동 화면 단지 표(1,155쪽) · 3D 동네 지도 | `loadDongComplexes`(RPC search_complexes_filtered) | `trade_count` 0 인 행을 뺀다. 페이지 끝 판정은 RPC 행 수로(걸러낸 수로 하면 일찍 멈춘다). 세는 단지 수도 "매매 실거래" 기준이 된다 |
| 검색 — 조건 검색("상계동" · "마포구 신축") | `runFilteredSearch` | 결과 목록에서 뺀다 · 총 개수(범위 설명)는 MV 그대로 |
| 검색 — 이름 검색("신이모닝빌" 3곳 중 1곳이 전월세만) | `searchComplexPreviews` | 결과에서 뺀다 |
| 단지 화면 "인근 단지" | `complex_tx_stats_base`(매매 집계표) | 원래 안전 — 확인만 |

`trade_count` 가 null 인 행(옛 RPC 판)은 "모름"이라 둔다. 운영 실측: 상계동 단지 112곳 → 매매 실거래 있는 105곳.
