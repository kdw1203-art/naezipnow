# 999 — 개편 9판: 좌측 내비를 "가장자리 hover 오버레이"로 · 헤더 드롭다운 복원 · 누락 보완

소유자 지시(2026-09-14, 998 배포 화면을 보고): "좌측 내비는 마우스가 왼쪽으로 갔을 때만 나오도록 액션형으로
접히는 형식으로만, 헤더 메뉴는 마우스를 올리면 보여지는 방식으로. 다른 개선사항 제안 + 누락 보완."

## 한 줄

**데스크톱 본문은 다시 1240px 한 열. 좌측 내비는 평소엔 없고, 마우스가 화면 왼쪽 가장자리(14px)에 닿으면
미끄러져 나와 벗어나면 접힌다. 헤더 4메뉴는 lg 에서도 hover 로 드롭다운을 연다. 998 이 2열 때문에 접었던 홈
지역 카드 4열, 작성 중 잃던 "내 판단", 목록에 섞여 있던 폐지 구를 같이 되돌리고 보완했다. 운영 경보 판은
"울린 것"과 "지금도 울리는 것"을 가르고, 1회짜리 일시 실패를 critical 로 올리던 검사 둘을 고쳤다.**

## 바뀐 것

### 999-1 · 좌측 내비 — 액션형 오버레이 (소유자 지시)
- `DesktopSideNav`: `lg+` 에서만. 화면 왼쪽 가장자리 **14px 핫존**에 마우스가 닿으면 패널(232px, 헤더 아래 82px 부터,
  유리 표면)이 180ms 로 미끄러져 나온다. 패널 밖으로 나가면 220ms 뒤 접힘(살짝 벗어난 손떨림에 안 닫히게),
  **Esc** · **경로 이동** · **Tab 이 패널 밖으로 나감** 에도 접힌다. 왼쪽 중앙에 10px 손잡이(알약) — 마우스가 없어도
  focus/click 으로 열린다(`aria-expanded`/`aria-controls`, 접혀 있을 땐 링크 `tabIndex=-1` 로 Tab 순서에서 제외).
- 본문 폭을 차지하지 않는다: `PageShell`·홈의 `<main>` 은 998 이전과 같은 1열(`.nz-shell:has()` 그리드 삭제).
  내비는 `<main>` 밖 형제라 `data-autotrim`·스킵 링크 영향 없음.
- 내용은 998 과 같음: 임장노트 · 지도 · AI 분석 · 동네 · 마이(관심·기록·포인트·설정) 22행, 현재 경로 `aria-current`.
  `/admin` `/login` `/signup` `/map` `/embed` `/welcome` `/notes/[id]/card` 에는 없다.

### 999-2 · 헤더 드롭다운 hover 복원 (소유자 지시)
- 998 이 lg+ 에서 감췄던 드롭다운(`lg:hidden`) 되돌림 — md 이상 모든 폭에서 hover/focus-within 으로 연다.
  좌측 내비는 가장자리에서만 나오므로 둘이 겹치지 않는다.

### 999-3 · 누락 보완
- 홈 지역 시세 카드 `xl:grid-cols-4` 복원 — 998 이 본문 폭 축소 때문에 2열로 고정했던 것. 본문이 1240 으로 돌아왔다.
- 임장노트 작성 3단계 **내 판단(살까·보류·패스·다시 보기 + 근거)** 이 localStorage 임시 저장(`NoteDraft.decision`)에
  포함 — 996 에서 판단 UI 를 넣을 때 초안 복원에서 빠져, 새로고침·이탈 후 돌아오면 판단만 사라졌다.
  복원 시 `choice` 유효성·근거 ≤3 검증.
- 폐지 지역(인천 서구·중구, 2026-07 개편)을 **목록·선택지**에서 뺀다: 동네 홈 "다른 동네"(`groupRegionsByCity`),
  지역 월간 리포트 "다른 지역", 시나리오 지역 선택. 페이지 자체(`/region/incheon-seo` 등)와 id·이름 조회는 그대로
  (998 의 안내+후속 구 링크). `ACTIVE_REGION_CATALOG` 한 곳에서 거른다.

### 999-4 · 운영 경보 판 — "진행 중 / 해소" (소유자 화면 2차 지시)
- 소유자 화면(09-14 14:50 KST): "critical 7종"인데 실제 진행 중은 2종 — matview(09-09 해결)·apt-master(09-13 20:00 UTC
  ok 이후 정상)·CWV(994 봇 표본 제거로 해소)·뉴스(09-11 하루 결측 후 정상)가 7일 판에 그대로 critical 로 남아 있었다.
  로그는 "울린 것"만 쌓이고 "그친 것"은 안 쌓이기 때문.
- `lib/admin/health-alerts-fold.ts`(순수): 검사|심각도로 접은 뒤 **마지막 발생 시각**과 그 검사의 발생 간격(로그에서 도출)으로
  진행 중/해소를 가른다 — 시간 단위 검사는 마지막 발생 3시간 안, 일 단위(또는 1건뿐)는 27시간. 정렬: 진행 중 → critical →
  최근 순. 판: "critical N종 진행 중" 또는 "진행 중 critical 없음" 배지, 행마다 **진행 중 / 해소 · N시간(일) 전** + 마지막
  발생 KST, 해소 행은 흐리게. 상단 빨간 배너는 진행 중 critical 만 센다("(24시간)" → "진행 중").
- 헬스체크 오탐 둘 수정(마이그레이션 `999_ops_transient_cron_failure_not_critical`, 적용 완료):

    "이후 성공 없음(중단 상태)" critical 로 적었다. 다음 회차(00:30)가 아직 안 온 것뿐. 새 규칙: 연속 2회 실패 · 일/주 단위
    잡 · 주기+15분이 지나도록 실행 없음 → critical, 시간 단위 잡의 1회 실패는 warn "재시도 대기". 주기는 최근 7일 실행
