# 975 — 지도·검색으로 시작하는 AI 분석 + 시인성 실측 개선 (2026-09-08)

소유자 지시 두 가지.

1. **"AI 분석에서 해당 기능을 누르면 지도도 같이 떠서 그 지도를 통해서 바로
   진단·예측·동선분석 등을 할 수 있도록"**
2. **"다른 기능들에 들어갔을 때 시인성 개선 작업도 진행해주고, 단지나 지역 검색을
   통해 상세하게 분석하고 결과값을 제공할 수 있도록 대규모 개편"**

---

## 1. 분석의 출발점이 "이름을 아는 단지" 하나뿐이었다

여태 분석 도구를 시작하는 길은 **글자 검색 하나**였다. 단지 이름을 정확히 알아야
아무것도 시작할 수 없다는 뜻인데, 임장은 보통 반대 순서다 — 지도를 보다가 "여기
뭐지?" 로 시작한다. 그래서 검색이 서 있던 자리마다 지도를 붙였다.

### 도구 카드를 누르면 지도가 함께 뜬다

`/analysis` 워크벤치 카드(이 단지 종합 진단·시세 예측·임장 동선·매수 타이밍 …)를
**고른 단지 없이** 누르면, 예전에는 빈 도구 화면이 열리고 거기서 다시 단지명을
입력해야 했다. 이제 그 클릭이 지도 서랍을 연다. 지도에서 마커를 누르거나 서랍 안
검색으로 고르면 **그 도구가 그 단지로 곧장 열린다**(`?complexId=`).

막다른 길은 만들지 않았다.

- 이미 단지를 골라 뒀으면 카드는 예전처럼 바로 이동한다.
- ⌘/Ctrl·Shift 클릭, 가운데 클릭(새 탭)은 가로채지 않는다.
- 서랍 안에 "단지 없이 〈도구 이름〉 먼저 보기 ›" 를 둔다 — 도구가 어떤 건지 먼저
  보고 싶은 사람을 막지 않는다.
- Esc·바깥 클릭·닫기(×) 로 언제든 나온다.

### 검색이 있는 자리마다 같은 지도

`ComplexPicker` 옆 단추가 하는 일을 부르는 쪽이 정하게 했다(`onMapClick`).

| 화면 | 예전 | 지금 |
|---|---|---|
| /analysis 히어로 | `/map` 으로 나갔다가 `?complexId=` 로 돌아옴 | 그 자리에서 지도 서랍 |
| /analysis/ai/[tool] | 검색만 | 지도 서랍 (도구 이름이 서랍 제목) |
| /analysis/scenario | 검색만 | 지도 서랍 → 기준가·지역 프리필 |
| /analysis/compare | 검색만 | 지도 서랍 → 비교 트레이에 담기 |
| /analysis/timing | 검색만 | 지도 서랍 → 그 지역으로 전환 |

지도로 고르든 검색으로 고르든 결과는 **같은 값**이다(`resolvePickedComplexById` 한
군데서 조립). 두 경로가 각자 조립하면 지역 표기·시세 라벨이 갈린다.

### 예산 안에서 — 열기 전에는 한 바이트도 안 받는다

`/analysis` 는 First Load JS 예산 여유가 몇 KB뿐이다. 지도(`NaverMap`, 1,344줄)를
얹으면 그 자리에서 깨진다. 그래서 (a) 서랍을 `dynamic(ssr:false)` 로만 부르고,
(b) **열렸을 때만 자리에 놓는다** — `next/dynamic` 은 *그려지는 순간* 내려받으므로
`open={false}` 로 놓아 두면 지도를 한 번도 안 연 사람도 묶음을 받는다.

덤으로 첫 묶음을 실제로 줄였다. `ComplexPicker` 가 끌고 오던 지역 카탈로그
(`lib/map/seoul-districts`, ≈14KB)는 **단지를 고른 뒤에야** 필요한데 첫 화면에
얹혀 있었다. 지금은 하이드레이션 뒤 한가할 때 미리 받아 두고 쓴다.

| 라우트 | 작업 전 | 작업 후 | 예산 |
|---|---|---|---|
| /analysis | 489KB (지도 추가 시 493KB) | **486KB** | 490KB |
| /analysis/ai/[tool] | 465KB | **458KB** | 480KB |

### 지도가 안 뜨는 날 거짓말하지 않기

경계값을 서랍이 스스로 계산하고 있었다(`level < 7` 이면 개별 단지). 그런데
`/api/map/clusters` 의 경계는 `zoom ≥ 14` = `level ≤ 7` 이라 **정확히 level 7 에서
어긋났다** — 서버가 단지 300곳을 보내는데 화면은 "이 화면에는 실거래가 있는 단지가
없어요" 라고 말했다. 경계값을 `lib/map/pick-zoom.ts` 한 곳으로 올리고, 모드는
서버 응답(`mode`)을 그대로 따르게 했다. 관계는 단위검증이 잠근다
(`tests/unit/map-pick-zoom-975.test.ts`).

지도 SDK 가 안 뜨면 `NaverMap` 은 OSM 대체 화면으로 내려가는데, 거기엔 마커가 없다.
그때 "단지가 없어요" 는 거짓말이므로 **"지도를 불러오지 못했어요 — 위 검색창에
단지명을 넣어 주세요"** 로 사실대로 말하고 검색으로 안내한다.

## 2. 시인성 — 눈으로 고르지 않고 **재서** 고쳤다

렌더된 화면의 실제 픽셀에서 전경·배경을 합성해 대비를 재고(조상 opacity 포함),
WCAG AA 미달만 골라 고쳤다. 아래 숫자는 전부 실측이다.

### 2-1. 투명도로 흐리게 만든 것들 — 글자까지 같이 사라졌다

`opacity` 는 배경만이 아니라 **글자까지** 반투명하게 만든다.

| 자리 | 전 | 후 |
|---|---|---|
| 워크벤치 "③ 분석 실행"(비활성) | `disabled:opacity-50` — 흰 글자가 녹아 다음 할 일이 안 읽힘 | 연한 채움 + 진한 글자 (`.btn-primary:disabled`) |
| 동네이야기·뉴스·알림·단지 탭 카운트 | `opacity-70` → 2.87~3.54 | 부모 색 그대로 (측정: 어떤 opacity 도 4.5 를 못 넘긴다) |
| /town 피드 눈썹 | `opacity-70` | `text-text-3` |

비활성 버튼은 "못 누른다"는 신호는 유지하되(연한 면·not-allowed) **무엇을 누르게
될지는 읽혀야** 한다 — 분석 화면에서 그 버튼은 안내문이기도 하다.

### 2-2. 어두운 면 위 토큰이 밝은 면에 얹혀 있었다

| 자리 | 전 | 후 |
|---|---|---|
| 도구 머리 "넣는 것/계산/나오는 것" 패널 | `bg-on-dark-faint`(45%) → 네이비 위 #75818E, 글자 **3.53** | `bg-on-dark-panel`(12%) → **9.85** |
| 도구 머리 "AI 분석" 빵부스러기 | 전역 링크 파랑, 네이비 위 **2.32** | `text-on-dark` |
| /analysis/timing "단지로 지역 찾기" 라벨 | `text-text-3`, 네이비 위 **2.80** | `text-on-dark-muted` |
| /town "지금 이 피드에 실린 글 기준" | `text-on-dark-faint` **3.86** | `text-on-dark-muted` **7.69** |
| /auctions 달력 흐린 날짜 | `text-on-dark-muted`, 밝은 칸 위 **1.05** | `text-text-3` |
| /auctions "전체" 칩 | 인라인 `color:#fff` 잔재, 한지 위 **1.13** | 클래스가 정한 색 |

`--on-dark-faint`(45%)는 **선·구분자용**이다. 패널 바탕으로 쓰라고 `--on-dark-panel`
(12%)을 새로 뒀다.

### 2-3. 토큰 자체가 미달이던 것

- `--brand-red-on-dark` `#E0563A` → `#E96A4B` : 네이비 위 **4.08 → 4.86**.
  ("플랜 보기 ›", 히어로 눈썹 글자가 실제로 흐렸다. 채움으로 쓰이는 자리는
  온점·링·스위치 손잡이뿐이라 밝아져도 잃는 게 없다.)
- `--primary-fill` **신설** `#2f62e2` : 시나리오 막대가 `var(--primary)`·`--danger`·
  `--ai-accent` 를 흰 글씨 채움으로 쓰고 있었다. `--ai-accent`(어두운 패널용)는 밝은
  카드 위 흰 글씨가 **2.27**. 이제 셋 다 채움 전용 토큰이고, 색의 뜻도 맞다
  (붉음 = 부담 증가, 초록 = 감소).
- 하우스 광고 커버 그라데이션 끝색 `#2fa3e0` → `#186f9f` : 오른쪽 칩이 그 색 위에
  앉는데 흰 글씨 **2.82 → 5.51**.
- 홈 티커 `text-white/45` → `text-on-dark-muted` : 네이비 위 **4.21 → 7.69**
  (axe 실측). 952 규칙상 어두운 면 위 글자는 흰색이 아니라 한지 계열이다.
- 하단 탭바 비활성 라벨 `text-text-3` → `text-text-2` : 반투명 유리 뒤 배경이 비쳐
  실제 바탕이 #d1d6dc 가 되고 거기서 **3.75** 였다(axe 실측). 이 라벨은 모든 화면
  아래에 늘 떠 있다.

### 2-4. 화면별 테마가 통째로 미달이었다 — /supply 한 화면에서 243건

`/supply`(초록)·`/dev-deals`(앰버)는 `--primary` 계열만 갈아 끼우는데, 그 값을
`text-primary`·`bg-primary-soft`·`chip-active` 같은 **공용 클래스**가 그대로 쓴다.
색이 밝으면 그 화면 전체가 한꺼번에 미달이 된다.

| 테마 | 전 (자기 soft 위) | 후 |
|---|---|---|
| /supply 초록 `#0e9f6e` | **3.04** | `#0a7a55` **4.79** |
| /dev-deals 앰버 `#d97706` | **2.86** | `#a4570a` **4.78** |
| /qna 청록 `#0d9488` | **3.32** | `#0a7168` **5.21** |

두 화면은 테마가 `page.tsx` 인라인 `style` 이었다. 970 이 `/auctions` 에서 고친 것과
같은 문제를 그대로 갖고 있었다 — 라이트 값만 심어 **다크에서 연한 판이 형광처럼
떴고**, 인라인이라 대비 게이트가 볼 수 없었다. `.theme-supply` / `.theme-dev-deals`
클래스로 옮기고 다크 값을 붙였다.

## 3. 다시 태어나지 않게 — 게이트를 고쳤다

`scripts/check-contrast-tokens.mjs`:

1. **다크 검사가 여태 라이트를 두 번 보고 있었다.** 블록을 `indexOf(".dark")` 로
   찾는데 globals.css 주석의 "라이트(:root)·다크(.dark) 양쪽에" 라는 **문장**이 먼저
   걸렸다. "dark — 50조합 통과" 는 사실이 아니었다. 규칙 머리로만 찾도록 고쳤고,
   그러자 곧바로 `--primary-fill` 이 다크 표면과 2.60:1(비텍스트 최소 3) 로 걸렸다.
2. **네이비 위 조합**을 약속에 넣었다(`on-dark`·`on-dark-muted`·`brand-red-on-dark`
   × `brand-navy`·`on-dark-panel`). 이번에 무너진 자리가 전부 여기였다.
3. **화면 테마 4종**(/auctions·/qna·/supply·/dev-deals)을 라이트·다크 양쪽으로
   검사한다. 여기 들어오려면 테마가 CSS 클래스여야 한다 — 그래서 두 화면을 옮겼다.
4. `--primary-fill` 을 채움 토큰 목록에 넣었다(흰 글씨 AA + 표면과 3:1 분리).

## 5. 남겨 둔 것 — 다음 판단이 필요한 자리

정직하게 적어 둔다. 재 봤고, 이번에 손대지 않기로 한 것들이다.

1. **다크 모드에서 파랑·보라·초록 채움 버튼 위 흰 글자가 3.18~3.21:1.**
   `bg-primary`·`.btn-primary` 가 다크에서 `--primary`(밝은 색)로 뒤집히기 때문이고,
   970 주석이 "흰 글자 버튼도 루트와 같은 3.2:1" 이라고 **이미 받아들인** 상태다.
   앱 전체 버튼 색이 바뀌는 변경이라 지시 없이 하지 않았다. 고치려면 테마마다
   `--primary-fill` 을 두고 다크에서 채움만 그 값을 쓰면 된다.
2. **`/notes` 카드 제목**(사진 위 흰 글자) — 스크림(`from-black/78`)과 그림자가 있고
   사진마다 달라 정적으로 못 잰다. 스크림을 위쪽까지 올릴지는 디자인 판단.
3. **`npm run check:sidebar-grid`** 가 `app/subscription/page.tsx` 3곳에서 실패한다.
   origin/main 에서도 같다(이번 변경과 무관, 빌드 게이트 체인 밖).
