# 화면 구성 원칙 — 데스크톱·모바일 (1015)

소유자 지시(2026-09-28): "전체적으로 데스크탑도 밀도를 올려주는데, 필요한 부분에 대해서는 사이즈 조절 등을 통해서
빈공간 확보도 해주는 등의 유연성 있는 화면 구성을 도입해줘. 사용자가 데스크탑·모바일 화면을 볼 때 어떤 식으로
구성하고 어떤 방식으로 보여지는지 효과적인 뉴스기사나 연구보고서, 참고문서나 자료 등이 있으면 그걸 바탕으로
도입해줘. 검토 후에 사이트의 페이지 전체에 도입해줘."

이 문서는 검토한 자료와, 그 자료에서 사이트 전체 규칙으로 옮긴 것을 적는다. 규칙은 전부 `app/globals.css` 의
토큰 한 곳에서 걸려 페이지마다 다시 손대지 않는다.

## 1. 검토한 자료

### 1-1. 사람은 화면을 F 자로 읽는다 — Nielsen Norman Group, *F-Shaped Pattern of Reading on the Web* (2006, 2017 갱신)

시선 추적 결과 사람은 웹 화면을 위 두 줄은 가로로, 그 아래는 왼쪽 세로로 훑는다. 첫 두 문단, 제목의 첫 두 단어에
핵심을 앞세우고, 핵심 어구는 굵게, 관련 내용은 묶어서 보이라는 권고. 모바일에서도 같은 형태가 관찰된다.
→ 사이트 규칙: 카드·행의 첫 줄은 제목, 둘째 줄은 지역·출처·날짜(메타). 설명문은 제목 뒤가 아니라 ⓘ(Explain) 안으로.
뉴스룸 "많이 본 뉴스"는 숫자 + 제목 한 줄. 부연 라벨("사람의 기록", "자동 수집 최신")은 F 의 읽기 경로를 끊는
장식이라 제거.

### 1-2. 손 잡는 방식과 엄지 범위 — Steven Hoober, *How Do Users Really Hold Mobile Devices?* (UXmatters, 2013)

1,333명 관찰: 한 손 49%, 받쳐 잡기 36%, 두 손 15%. 한 손 사용자의 67%가 오른손 엄지. 화면 아래·가운데가 엄지의
편한 영역, 위쪽 모서리가 가장 어렵다.
→ 사이트 규칙: 주 조작(탭바·저장·다음)은 화면 아래에 두고, 위쪽은 읽기 전용. 40px 조작 하한은 모바일 축소
([1012]) 뒤에도 고정. 폰에서 카드 패딩·간격은 줄이되 탭 표적은 줄이지 않는다.

### 1-3. 본문 줄 길이 — Baymard Institute, *Readability: The Optimal Line Length* ; WCAG 2.1 SC 1.4.8

한 줄 50~75자가 읽기 속도·이해도에서 가장 좋고(Baymard), WCAG 1.4.8 은 80자 이하를 권고. 너무 긴 줄은 다음 줄
찾기가 어렵고, 너무 짧은 줄은 시선이 자주 되돌아와 피로하다.
→ 사이트 규칙: 본문(.prose, 안내문)은 `max-w-[640px]`(한글 13px 기준 약 48~50자, 영문 혼용 시 60~70자) 안에.
데스크톱에서 카드가 넓어지면 본문을 늘리지 말고 **옆 칸**(요약·광고·관련 글)을 세운다 — 아래 2-3.

### 1-4. 밀도의 뜻 — 정보 밀도 vs 시각 밀도

같은 화면에 정보를 더 실으려면 글자를 줄이는 게 아니라 **간격**을 줄여야 한다. 글자를 줄이면 가독성이 먼저
떨어진다(1-3). 데스크톱은 시야 거리가 모바일보다 멀어 글자 크기는 유지하고, 여백만 조인다.

## 2. 사이트에 옮긴 규칙

### 2-1. 데스크톱(md+) — 글자 유지, 간격 0.875 배

`app/globals.css` `@media (min-width: 768px)`:

- `--spacing: 3.5px` (4px × 0.875). Tailwind v4 의 모든 숫자 간격·크기 유틸(`p-4` `gap-3` `mt-6` `h-12` …)이
  `calc(var(--spacing) × N)` 이라 11,000여 곳이 한 번에 같은 비율로 줄어든다. px 로 적은 임의값(`h-[44px]`
  같은 "정확해야 하는 크기")은 그대로.
- 카드 패딩 `--pad-card` 18 → 16, 히어로 `--pad-hero` 22 → 20.
- 글자 토큰(`--fs-display 28` · `--fs-title 21` · `--fs-section 15` · 본문 13)은 변경 없음.
- 40px 조작 하한 고정(`.h-10 .min-h-10 .w-10 .min-w-10 .size-10`) — 마우스도 표적이 작으면 클릭 오차가 는다.

### 2-2. 모바일 — [1012] 그대로

뷰포트 배율 0.75(`html[data-mscale]`) + 간격 3px + 카드 패딩 9/13 + 한 줄 말줄임. 이번에 캡션 글자
`--fs-caption` 12px(11 → 12: 배율 0.75 뒤 화면 9px 는 너무 작았다), 빈 상태 그림 64px.

### 2-3. "빈공간 확보" — 페이지별 lg: 2단 레일

넓은 화면에서 본문을 늘리는 대신 `lg:grid-cols-[minmax(0,1fr)_340px]` 로 오른쪽 레일을 세운다. 레일에는
요약·많이 본 글·구독·광고(`AdZone`)가 들어가고, 모바일에서는 본문 아래로 내려간다. 1015 에서 적용:
뉴스룸(`/town/news`), 임장노트 목록·상세, 단지, 동네 서브(청약·공급·경매·정비), 분석 도구, 요금제·내 정보,
여정·리포트·실거래·가이드 등 — 담당 5인 보고서(`docs/release-1015.md`) 참조.

### 2-4. 광고 자리

- 데스크톱: 오른쪽 레일 첫 칸(`AdZone` sidebar) + 페이지 끝(`page_bottom`).
- 모바일: 첫 목록 바로 아래 1회(`home_feed` 등, `lg:hidden`) + 페이지 끝. 화면 상단 히어로 안에는 두지 않는다
  (1-2: 위쪽은 읽기 영역).

### 2-5. 썸네일

- 임장노트: 자동 생성 표지(`/api/og/note-cover/[id]`). 목록 행 44px 정사각, 피드 카드는 `shape=wide`
  1200×630 을 `aspect-ratio: 1200/630` 칸에 — 비율이 어긋나 잘리던 문제([1015] 소유자 지적) 해결.
- 뉴스: 기사 원본 사진만(`newsImageUrl`). 사진이 없으면 신문 아이콘 — 매체 이름 글자 칸은 쓰지 않는다.

### 2-6. 글

- 설명·안내는 ⓘ(`Explain`)로 접는다. 데스크톱은 마우스를 올리면 미리보기, 모바일은 탭.
- 부연 라벨("사람의 기록" · "자동 수집 최신" · "Lab 데이터 카드")은 쓰지 않는다.
- 카드 색은 테마(`data-tone` blue/hanji/mint/sand) 안에서만. 튀는 배경색·그라데이션 없음(`check-ai-look`).

## 3. 검증

- `npm run build` 게이트 전부(디자인 v3 · 모바일 탭 하한 · 번들 예산) 통과.
- 데스크톱 1280 · 모바일 390 스크린샷 전후 비교(홈·노트·동네·뉴스·단지·요금제) — 릴리스 노트에 첨부.
