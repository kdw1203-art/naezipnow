# 978 — 동네이야기 하위 9칸에 홈과 같은 머리 (2026-09-08)

소유자 지시: **"동네이야기에서 각 하부 카테고리를 들어가더라도 (홈 머리가) 고정되면
좋겠다. 고정은 되되, 각 하부 카테고리 주제에 맞게 내용이나 기능, 약간의 부연설명
정도가 변경되는 수준으로."**

범위와 변주 항목은 소유자가 골랐다 — **히어로 + 9칸 격자까지 고정**, 바뀌는 것은
**제목·설명 / 통계줄 / 오른쪽 버튼 / 아이콘·색** 네 가지.

---

## 1. 왜 필요했나

974 에서 9칸의 **작은 머리**(아이콘 칩 + 제목 + 한 줄)는 통일했다. 그런데 홈(/town)에
들어갔다가 카테고리로 한 발 들어가면 화면의 격이 갑자기 낮아진다 — 홈은 네이비
히어로인데 하위는 흰 바탕 한 줄이라, 같은 동네이야기 안에 있다는 느낌이 끊긴다.

그래서 히어로를 하위에도 세우고, **안에 넣는 말만** 카테고리를 따라 바꾼다.

## 2. 무엇을 고정하고 무엇을 뺐나

| 블록 | 홈 | 하위 9칸 |
|---|---|---|
| 네이비 히어로 | ✅ | ✅ (카테고리별 변주) |
| 카테고리 9칸 격자 | ✅ | ✅ |
| 지역 칩(우리 동네 홈) | ✅ | ❌ |
| 오늘의 동네 글감 | ✅ | ❌ |

뒤 둘을 뺀 이유: "동네 고르기"와 "글 쓸 거리"는 카테고리 본문과 성격이 다르고,
넣으면 본문이 한 화면 아래로 밀린다.

## 3. 무엇이 바뀌는가 — 네 가지

**① 제목·설명** — `heroTitle`([앞, 강조, 뒤] 세 토막) + 기존 `headSub`.
홈이 "다녀온 사람의 기록이 **지금** 동네를 말합니다" 인 것과 같은 모양으로,
강조 한 단어만 주홍으로 뜬다.

| 카테고리 | 제목 |
|---|---|
| 뉴스 | 오늘 부동산은 **이렇게** 움직였습니다 |
| 청약 센터 | 이번 달 청약, **경쟁률**까지 보고 정합니다 |
| 공매 물건 | 감정가보다 싼 물건이 **지금** 입찰 중입니다 |
| 입주 물량 | 언제 어디에 **얼마나** 들어오는지 봅니다 |
| 정비사업 지도 | 우리 동네 재개발이 **어디까지** 왔는지 봅니다 |
| 단지 Q&A | 살아 본 사람만 아는 답이 **여기** 있습니다 |
| 전문가 | 자격을 확인한 전문가에게 **직접** 묻습니다 |
| 임장 모임 | 같은 단지를 **함께** 도는 이웃을 찾습니다 |
| 자료 | 남이 다녀온 기록이 **내** 임장을 줄입니다 |

문장은 전부 `lib/town/category-links.ts` 한 곳에 있다. 974 에서 본문과 로딩
스켈레톤이 어긋났던 이유가 같은 문장을 두 곳에 적어서였다 — 그 규칙을 그대로 잇는다.
파싱 규칙(`*강조*` 같은 표기)을 만들지 않고 세 토막으로 받는 이유도 같다:
규칙이 생기면 문구를 고칠 때마다 그 규칙을 기억해야 한다.

**② 통계줄** — 페이지가 **자기 화면의 실측**을 넘긴다.

| 카테고리 | 통계 | 근거 |
|---|---|---|
| 뉴스 | 오늘 기사 · 이 화면 N건 | 이미 읽어 둔 `news` 배열 |
| 정비사업 지도 | 지도에 실린 구역 N곳 | `projects.length` |
| 전문가 | 인증 전문가 N명 · 누적 상담 답변 N건 | `verified.length` · `answered` |
| 임장 모임 | 모집 중인 모임 N개 | `views.length` |
| 자료 | 리포트 N건 · 공개 임장노트 N건 | `reports.length` · `notes.length` |
| 청약·공매·입주·Q&A | (없음) | 아래 참고 |

두 규칙을 홈에서 그대로 가져왔다.

- **0 은 그리지 않는다.** "오늘 새 글 0" 은 살아 있다는 신호가 아니라 비었다는
  고백이다(970 · C-30). `value <= 0` 인 칸은 통째로 빠지고, 남는 칸이 없으면
  통계줄 자체가 사라진다.
- **무엇을 센 건지 적는다.** "지금 이 화면에 실린 기사 기준" 처럼 모수를 밝힌다.

그리고 하나 더 — **여기서 새로 세지 않는다.** 청약·공매·입주·Q&A 는 숫자가
클라이언트 조각 안에 있어서, 통계를 넣으려면 서버에서 조회를 새로 해야 한다.
976 에서 DB 왕복을 줄여 놓고 머리를 붙이면서 9개 화면에 조회를 얹으면 그건
되돌리는 짓이다. 그래서 그 넷은 통계줄 없이 간다.

**③ 오른쪽 버튼** — `heroCta`. 없으면 안 그린다(없는 버튼을 지어내지 않는다).
뉴스=주간 다이제스트 · 청약=청약 캘린더 · 전문가=전문가로 참여 · 자료=임장노트 쓰기.
모임은 클라이언트 조각(`CreateGroupCta`)이라 페이지가 `action` 으로 덮어쓴다.
옆 카테고리로 보내는 링크는 넣지 않았다 — 그 이동은 바로 아래 9칸 격자가 이미 한다.

**④ 아이콘·색** — 카테고리 아이콘 + 고정색 칩.

## 4. 색을 왜 새 토큰으로 뒀나

9칸 카드가 쓰는 `tone`(`bg-primary-soft text-primary` 등)을 네이비 히어로에 그대로
얹을 수 없다. **그 값들은 테마를 탄다** — 다크에서 `--primary-soft` 는 #1a2540 이라
네이비(#0B2545) 위에서 칩이 사라진다. 네이비 카드는 테마와 무관한 고정면이므로
그 위의 색도 고정이어야 한다.

그래서 `--on-navy-blue/green/amber` 세 토큰을 뒀다. 칩 바탕은 975 에서 만든
`--on-dark-panel`(한지 12%)이고, 그 위 실측은 파랑 5.31 · 초록 5.40 · 주황 5.22 —
비텍스트 최소 3:1 을 넉넉히 넘는다.
`#8fb3ff` 는 `.toast-action` 이 "네이비 위 링크 파랑"으로 이미 쓰던 값이라,
raw hex 한 곳을 토큰으로 걷어내는 정리도 겸했다.

## 5. 곁가지 하나 — 또 투명도였다

`/town/experts` 한지 띠의 문단이 `opacity-80` 이었는데, 그 안에 링크
(`/legal/expert`)가 있었다. 부모 투명도가 링크 색(`--primary`)까지 흐려
한지 위 **4.07:1**(axe 실측). 976 에서 고친 것과 같은 부류다 — 투명도로 흐리게
만들면 글자까지 같이 사라진다. 크기(`t-caption`)가 이미 위계를 말하므로 색은
그대로 두고 `opacity-80` 만 뺐다.

## 7. 남겨 둔 것

- **청약·공매·입주·Q&A 통계줄** — 숫자가 클라이언트 조각 안에 있다. 서버로 끌어올리려면
  조회가 늘거나 데이터 흐름을 바꿔야 해서, 이번엔 넣지 않았다. 넣을 값이 생기면
  `TownHero` 에 `stats` 한 줄만 더하면 된다.
- `TownPageHead` 는 지웠지 않고 남겼다 — 카테고리 목록에 없는 **하위 상세** 화면이
  쓸 자리다. 9칸에서 다시 쓰면 홈과 머리가 갈라지므로 파일 상단에 그 사실을 적어 뒀다.
