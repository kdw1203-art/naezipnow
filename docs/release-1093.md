## 개편 1 — 공개 화면의 본문이 "숨은 조각"으로 저장되고 있었다

로컬 빌드의 저장 HTML 을 **JS 를 끈 채**(크롤러 · AI 봇이 읽는 그대로) 열어 보니:

| 화면 | 보이는 글자 | 숨은 조각(`<div hidden id="S:0">`) 안의 글자 |
|---|---|---|
| 단지 `/complex/[id]`(2.4만 쪽) | **999자 — 전부 셸(메뉴 · 푸터)** | **1,897자 — 제목 · 사실 · 실거래 · 요약 전부** |
| 뉴스 상세 · 구간 · 동네이야기 · 분석 · 입주 물량 · 리포트 · 임장 가이드 · 공개 노트 허브 | 셸 + 스켈레톤 | 본문 전부(공개 노트 허브는 350KB) |

원인: `loading.tsx` 가 만드는 Suspense 경계. React 는 ISR 첫 렌더를 스트리밍할 때, 또는 경계 안 본문이 12.8KB 를 넘을 때 본문을 `<div hidden>` +
`$RC` 바꿔치기 스크립트로 내보낸다. 브라우저와 Googlebot 은 스크립트로 제자리에 놓지만, **JS 를 돌리지 않는 크롤러와 AI 검색 봇**(1087 에서
일부러 열어 둔 GPTBot · ClaudeBot · PerplexityBot …)은 스켈레톤만 읽는다. 1081 에서 지역 상세 한 곳만 이 이유로 스켈레톤을 뺐고, 단지 화면은
"이동 중 흰 화면 방지"로 남겨 두었었다(최종 게이트 · 1066 정책).

  남은 스켈레톤은 로그인 뒤 화면(마이 · 알림 · 노트 쓰기) · 심사 고정 화면(요금제 · 포인트 상점) · 보관(Q&A) · 클라이언트 지도뿐 — 단위 테스트가
  전수로 잠근다.

  조회 예산까지 최대 8초). 1090 · 1092 로 셸이 레이아웃에 있으므로 이동 중에도 헤더 · 메뉴는 그대로 남고, 본문만 새 것으로 바뀐다.
- 404 판정 레이아웃(1066)은 그대로다. 최종 게이트(`check-final-release`)는 반대 방향으로 — "공개 화면에 loading 경계가 없다"를 확인한다.

## 개편 2 — 공개 노트 허브(`/notes`)

HTML 507KB 가운데 **42%(168KB)가 보이지 않는 피드 카드 30장**이었다. 세 보기(격자 · 표 · 피드)를 전부 HTML 에 그리고 CSS 로 숨기는 구조였는데,
첫 화면 기본은 폰 격자 · 데스크톱 표라 피드는 어차피 숨겨져 있었다(저장된 보기는 마운트 뒤 localStorage 에서 읽는다).
그리고 셸(PageShell)을 클라이언트 조각(NotesFeedClient)이 통째로 그려 헤더 · 옆 메뉴 · 푸터가 클라이언트 번들 · 수화 대상이었다.

| 무엇 | 전 | 후 |
|---|---|---|
| 피드 보기 | 늘 그리고 CSS 로 숨김 | **골라야 그린다**(`view === "feed" \|\| deskView === "feed"`) — 격자 · 표는 SSR 그대로(크롤러가 보는 목록 · 링크 같다) |
| 셸 | 클라이언트 조각 안 | `app/notes/(index)/layout.tsx` 한 벌(1087 · 1090 · 1092 와 같은 구조) |
